# День 12 — персонализация ассистента

В двенадцатом задании Бублик использует пользовательский профиль поверх трёх слоёв памяти из Дня 11. Пользователь больше не должен повторять в каждом запросе желаемый язык, подробность, стиль, формат и ограничения: активный профиль автоматически добавляется в prompt.

## Что хранит профиль

Каждый JSON-файл в `config/profiles/` содержит:

| Поле | Назначение |
|---|---|
| `id` | Стабильный идентификатор профиля |
| `name`, `role` | Имя и роль пользователя |
| `language` | Язык ответов |
| `detail_level` | Требуемая подробность |
| `style` | Стиль общения |
| `response_format` | Правила структуры ответа |
| `constraints` | Персональные ограничения |

Личность самого Бублика вынесена отдельно в `config/assistant.json`. Благодаря этому настройки ассистента и предпочтения пользователя не смешиваются.

В примере есть два контрастных профиля:

- `cheburator` — краткий ответ, вывод в начале, короткие списки;
- `scientist` — подробный анализ, разделы, сравнения и оценка рисков.

## Связь профиля с памятью

Профиль выбирается при создании диалога, а его `profile_id` сохраняется в таблице `conversations`. Поэтому после перезапуска программа автоматически восстановит не только историю, но и нужную персонализацию.

| Данные | Область видимости |
|---|---|
| Short-term сообщения | Текущий диалог |
| Working memory | Текущий диалог и задача |
| Long-term решения и знания | Все диалоги одного профиля |
| Предпочтения | Выбранный пользовательский профиль |

Long-term memory теперь содержит `profile_id`. Это не позволяет решениям одного пользователя попасть в контекст другого. Профиль можно сменить командой `/profile PROFILE_ID` только в пустом диалоге без рабочей памяти.

## Формирование каждого запроса

`MemoryPromptBuilder` собирает prompt в фиксированном порядке:

```text
assistant identity + invariants
user profile: language + detail + style + format + constraints
long-term memory выбранного профиля
working memory текущего диалога
последние 6 short-term сообщений
current user request
```

Профиль загружается внутри `get_context_preview()`, который вызывается перед каждым `process()`. Поэтому персонализация применяется автоматически ко всем запросам, даже если пользователь не упоминает свои предпочтения.

Команда `/context` показывает точный prompt до отправки в Groq.

## Запуск

```bash
pip install -r requirements.txt
python day-12-personalization/main.py
```

Основные команды Дня 11 сохранены. Добавлены:

- `/profile` — показать активный профиль;
- `/profile PROFILE_ID` — сменить профиль пустого диалога;
- `/context` — проверить, что профиль присутствует в запросе;
- `/dialogs` — создать другой диалог и выбрать другой профиль.

## Как проверить задание

### 1. Автоматические тесты без API

```bash
python -m unittest discover -s day-12-personalization -p "test_*.py" -v
```

12 тестов проверяют:

- загрузку разных профилей;
- разные personalization-блоки для одинакового запроса;
- автоматическое присутствие профиля в каждом запросе;
- сохранение профиля вместе с диалогом;
- изоляцию long-term memory между профилями;
- запрет опасной смены профиля в заполненном диалоге;
- сохранение short-term, working, state machine и invariants Дня 11.

### 2. Просмотр prompt

Создайте диалог с профилем `Чебуратор` и выполните:

```text
/context
```

В prompt должен присутствовать блок `[USER PROFILE — APPLY AUTOMATICALLY]` со стилем, форматом и ограничениями. Сам вопрос при этом не обязан содержать эти требования.

### 3. Сравнение реальных ответов

```bash
python day-12-personalization/experiment.py
```

Эксперимент отправляет один вопрос с одинаковой working memory двум профилям. Ответ Чебуратора должен быть коротким и начинаться с вывода. Ответ Доктора Лиры должен быть подробнее, содержать структуру и оценку рисков.

## Результат

Бублик стал персонализированным агентом: выбранный профиль устойчиво связан с диалогом, автоматически влияет на каждый ответ и не требует повторения предпочтений. Два профиля получают разные ответы на один запрос, при этом трёхслойная модель памяти Дня 11 продолжает работать, а долговременные данные пользователей не смешиваются.
