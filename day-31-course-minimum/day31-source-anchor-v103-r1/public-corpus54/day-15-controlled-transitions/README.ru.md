# День 15 — Контролируемые переходы состояний

Версия задания расширяет автомат Дня 13 и инварианты Дня 14. Переходы становятся явным контрактом агента, prompt, CLI и тестов.

## Контракт жизненного цикла

Состояния: `planning`, `execution`, `validation`, `done`.

| Текущее | Разрешённые переходы | Условие |
|---|---|---|
| planning | execution | Нужен непустой и явно утверждённый план |
| execution | validation, planning | Для validation нужно завершить все шаги; planning — контролируемое перепланирование |
| validation | done, execution | `done` только после PASS; ошибка проверки возвращает в execution |
| done | нет | Терминальное состояние |

Пауза не является пятым этапом. Пока задача на паузе, переходы и изменение прогресса запрещены; разрешено только явное возобновление. Состояние хранится в SQLite.

## Что добавлено

- `TaskState` задаёт допустимые состояния.
- `ALLOWED_TRANSITIONS` — единый граф переходов.
- `allowed_targets()` применяет guards и показывает только реально доступные сейчас переходы.
- Guards запрещают пропуски этапов и объясняют отказ.
- План утверждается отдельной командой `/task approve`; изменение плана сбрасывает утверждение.
- В prompt передаётся та же политика с запретом перескакивать этапы.
- Семантический postflight проверяет готовый ответ модели относительно текущего этапа и `expected_action`.
- Ответ с реализацией во время `planning` удаляется и заменяется детерминированным отказом.
- `/task status` показывает разрешённые переходы.
- Проверки инвариантов Дня 14 сохранены.

## Запуск и тесты

```bash
cd day-15-controlled-transitions
cp .env.example .env
python3 -m pip install -r requirements.txt
python3 main.py
python3 -m unittest discover -s . -p 'test_*.py' -q
```

Основной сценарий: `/task create`, `/task plan`, `/task approve`, `/task transition execution`, `/task complete`, `/task transition validation`, `/task check pass`, `/task transition done`.

35 тестов проверяют недопустимые прыжки, фактически доступные переходы в `/task status`, явное утверждение плана, блокировку преждевременной реализации, pause/resume, восстановление после перезапуска, prompt и совместимость с Днём 14. Используются Python 3.13, SQLite и Groq; Node.js и PostgreSQL не требуются.
