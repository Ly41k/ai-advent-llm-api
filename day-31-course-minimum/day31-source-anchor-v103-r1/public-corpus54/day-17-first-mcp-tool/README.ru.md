# День 17 — Первый MCP-инструмент

MCP-сервер вокруг GitHub REST API, подключённый к циклу tool calling агента
Бублик. Решение продолжает локальный подход через `stdio` из Дня 16.

## Как работает решение

1. `server.py` регистрирует `get_github_repo` через `@mcp.tool()`.
2. Аннотации типов и docstring формируют описание инструмента и JSON Schema
   входных параметров.
3. Агент получает список MCP-инструментов и передаёт их схемы модели.
4. Модель запрашивает `get_github_repo(owner, repo)`.
5. Агент выполняет инструмент через `ClientSession.call_tool()`.
6. MCP-сервер запрашивает данные репозитория через GitHub REST API.
7. Результат возвращается модели и используется в финальном ответе.

Инструмент возвращает название и владельца репозитория, описание, stars,
forks, количество открытых issues, основную ветку и URL.

## Установка и проверка

```bash
cd day-17-first-mcp-tool
python3 -m pip install -r requirements.txt
python3 test_day17.py
```

Тест проверяет преобразование ответа GitHub через детерминированный mock HTTP
transport и настоящую схему MCP-инструмента. Лимит GitHub API не расходуется.

## End-to-end демонстрация

```bash
python3 demo.py
```

Для демонстрации нужен интернет, но не нужен Groq API key. Приложение выполнит
реальный запрос к публичному GitHub API и покажет вопрос пользователя,
MCP-вызов, сырой результат инструмента и финальный ответ Бублика.
`GITHUB_TOKEN` для публичных репозиториев необязателен.

## Запуск с Groq

```bash
cp .env.example .env
# Добавьте GROQ_API_KEY в .env
python3 main.py
```

Пример запроса: `Расскажи о репозитории Ly41k/ai-advent-llm-api.`

## Соответствие заданию

- регистрация инструмента — `@mcp.tool()` в `server.py`;
- входные параметры — типизированные `owner` и `repo` в JSON Schema;
- возврат результата — нормализованные данные из GitHub REST API;
- подключение к агенту — MCP-схемы передаются модели в `agent.py`;
- вызов из приложения — инструмент выполняется в `demo.py` и `main.py`;
- использование результата — ответ инструмента добавляется как сообщение
  `tool`, после чего модель формирует финальный ответ.

Всё запускается локально через `stdio`. VPS, открытый порт, домен, Nginx и SSL
не требуются.
