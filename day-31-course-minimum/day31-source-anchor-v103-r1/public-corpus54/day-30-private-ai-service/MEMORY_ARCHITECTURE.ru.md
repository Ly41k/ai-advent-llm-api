# Непрерывная память Бублика

## Обязательный контракт

Основная SQLite — первоисточник всей сохранённой переписки. Ограничение окна
модели, возраст разговора, обновление индекса или смена модели не удаляют историю.
Обновления проходят через контролируемые миграции; перенос — через проверяемый
archive/restore в новую базу. Ошибка проверки не должна объявляться успехом.
Это требование сохранности данных, а не гарантия безошибочного воспоминания LLM.

Все обращения авторизуются по owner. «Вся история» означает всю историю,
доступную этому владельцу. Объединение памяти разных пользователей или общая
семейная память потребуют отдельной явной модели доступа.

## Слои и состояние реализации

| Слой | Назначение | Состояние 0.10.0 |
|---|---|---|
| Исходная история | Обе стороны переписки, даты, IDs, статусы, attempts/events и inference snapshots | Реализовано; schema 3 |
| Поисковый индекс | Нахождение фрагментов по всей доступной истории | Приватный восстановимый FTS5 cache |
| Обобщения | Итоги разговоров с источниками, временем и версией способа построения | Будущий отдельный слой |
| Факты и предпочтения | Утверждения, изменения, подтверждения и противоречия | Будущий отдельный слой |
| Контекст ответа | Ограниченная подборка оригинальных цитат и недавней переписки | Реализовано; immutable snapshot |

Индекс, embeddings или summary не должны становиться единственной копией
воспоминания. Обобщение обязано сохранять ссылки на исходные сообщения; замена
способа поиска не переписывает originals. UI/reply languages — технические
настройки владельца, не автоматически извлечённые долговременные факты. Будущие facts/summaries, которые нельзя
восстановить точно, должны иметь свои версионируемые таблицы и входить в backup;
их нельзя объявлять disposable cache только потому, что они получены из истории.

## Доступ к памяти

Веб-чат включён в режим поиска по умолчанию. Поиск охватывает все accepted user
messages и непустые terminal assistant messages независимо от возраста диалога
или успешности ответа. Queued/running assistant checkpoints доступны в обычной
истории, но ещё меняются и поэтому не становятся frozen источниками RAG.
После завершения/прерывания их сохранённый текст попадает в индекс.

Каждая цитата содержит роль, статус, дату, IDs, диапазон символов и SHA-256
полного текста. Assistant response — свидетельство о том, что ответил ассистент,
а не подтверждённый факт о пользователе. Partial response явно помечается.
Источник проверяется по основной базе при поиске и повторно при admission.

Поиск рассматривает весь корпус, но возвращает до трёх сообщений. Ограничение
результатов/контекста не ограничивает сохранённую память. Original-message API,
bounded conversation-window API и существующая pagination истории позволяют
читать исходный разговор независимо от inference budget. Модель пока получает
выбранные цитаты автоматически; самостоятельные дополнительные поиски и чтение
разговора моделью ещё не реализованы. Это будущий навык использования памяти.

Сервис принимает сменный `HistorySearch` backend. Контракт результата включает
policy_version, sources, indexed_messages, search_seconds и reason. ContextBuilder
и storage не доверяют backend авторизацию или содержание original quotations.
Backend policy сохраняется в snapshot. Семантический backend можно добавить
отдельно, не меняя IDs и публичный контракт источников; его ресурсный профиль и
качество потребуют замеров.

API v1 сохраняет историческое `use_memory=false` при отсутствии поля, включая
старые idempotency fingerprints. Веб-клиент всегда передаёт явное значение:
обычно true; false — при ручном отключении. Повтор исходного запроса сохраняет
его режим и snapshot. Reload/logout возвращает checkbox к true без web storage.

## Перенос и проверка

Schema 3 добавляет только RU/EN настройки владельца; прежние migrations
001/002 не изменены. Исходная история и прежние snapshots не переписываются. Архив содержит историю и snapshots;
owner/message/chat/generation IDs сохраняются. Производный FTS5 cache можно
перестроить на новом пути, не обращаясь к LLM. Архивы 0.8.0 совместимы.
Browser sessions сбрасываются и API tokens отзываются только в восстановленной
копии, пароли остаются. Настройки сервера и веса модели переносятся отдельно.

Архивы пока plaintext. Проверка хешей устанавливает согласованность, не подпись
и не шифрование. Физический перенос на другое железо, off-host encryption и
автоматическое расписание backup ещё требуют отдельной приёмки.

## Следующий этап: использование памяти

Проверять отдельно сохранность, поиск и применение найденного моделью.
Контрольные сценарии: воспоминание из старого диалога; вопрос о прежнем ответе
ассистента; RU/EN формулировки; неизвестный факт; исправленное предпочтение;
противоречие с датами; прерванный ответ; отсутствие доступа к чужой памяти.

Затем развивать смысловой поиск, разрешение отсылок, чтение окружающего разговора,
версионируемые summaries/facts и оценку достаточности evidence. Отдельное обучение
весов не требуется для первого этапа: сначала инструкции и проверяемая логика
сервиса. Молчаливое забывание или удаление оригиналов не добавляется.

См. [установку и проверки](RAG_MEMORY.ru.md), [перенос](MEMORY_PORTABILITY.ru.md)
и [будущие задачи](BACKLOG.ru.md).
