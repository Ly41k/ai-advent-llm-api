# День 19 — Композиция MCP-инструментов

Бублик автоматически выполняет цепочку из **трёх отдельных MCP-инструментов** в одном запуске. Используется публичный GitHub API из предыдущих дней; Groq и VPS для этого упражнения не требуются.

```text
search_repository(owner, repo) → данные репозитория
summarize_repository(repository=<точный результат поиска>) → сводка Markdown
save_report(summary=<точный результат обработки>) → путь сохранённого файла
```

`server.py` регистрирует инструменты и публикует входные схемы. `agent.py` через `ClientSession.list_tools()` проверяет их доступность и по очереди вызывает через `call_tool()`. Результат MCP декодируется из JSON, передаётся следующему инструменту и сохраняется в журнале шагов. Если любой шаг вернул ошибку, цепочка останавливается. Текст сводки создаётся по понятным правилам, без расхода токенов. Файлы сохраняются в `reports/`, которая исключена из Git; можно указать собственную папку через `BUBLIK_REPORT_DIR`.

## Установка и самостоятельная проверка

Из корня репозитория (рекомендуется Python 3.13):

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r day-19-mcp-composition/requirements.txt
.venv/bin/python day-19-mcp-composition/test_day19.py -v
.venv/bin/python day-19-mcp-composition/main.py Ly41k ai-advent-llm-api
```

Если команда `python3.13` отсутствует, используйте доступный совместимый Python 3.10+. Первые три команды работают без API-ключей и сетевых запросов GitHub: тест запускает настоящий MCP-сервер по stdio и локальную подмену GitHub API. Последняя команда обращается к `api.github.com`; для публичного репозитория токен необязателен. При ограничении GitHub API можно установить `GITHUB_TOKEN` в окружении.

Ожидаемая последовательность вывода: `[MCP] search_repository`, `[MCP] summarize_repository`, `[MCP] save_report`, затем `Saved report`. Проверьте `day-19-mcp-composition/reports/Ly41k-ai-advent-llm-api-summary.md`: описание, default branch, звёзды, форки и открытые issues должны соответствовать результату первого инструмента. Повторный запуск обновит тот же файл.

## Проверка требований

| Требование | Реализация | Тест |
|---|---|---|
| Несколько MCP-инструментов | Три `@mcp.tool()` в `server.py` | `list_tools()` возвращает три имени и схемы |
| Первый получает данные | `search_repository` → GitHub REST API | Локальный fake API, проверка `stars = 12` |
| Второй обрабатывает | `summarize_repository` → Markdown | Сверка `Stars: 12` |
| Третий сохраняет | `save_report` → `.md` | Сверка содержимого файла и числа байт |
| Автоматическая цепочка | `BublikPipelineAgent.run()` выполняет вызовы подряд | Тест запускает `main.py` одной командой, проверяет порядок трёх вызовов и файл |
| Передача данных | Следующий аргумент равен полному результату предыдущего MCP-вызова | Проверка точного равенства словарей на обеих границах |
| Ошибка в середине | Остановка цепочки без отчёта | HTTP 503 не создаёт файл |

Сводка фиксирует текущий снимок репозитория, поэтому числа могут измениться со временем. День 18 запускал отдельный worker по расписанию; здесь цепочка выполняется сразу по команде пользователя.
