# День 13 — состояние задачи (Task State Machine)

В тринадцатом задании состояние задачи оформлено как конечный автомат. Бублик хранит не только описание и план, но и формальный этап, текущий шаг, ожидаемое действие и паузу. Эти данные сохраняются в SQLite и автоматически возвращаются в prompt после перезапуска.

## Модель состояния

Основной маршрут:

```text
planning → execution → validation → done
               ↑           |
               └── fail ───┘
```

| Поле | Назначение |
|---|---|
| `state` | Текущий этап: `planning`, `execution`, `validation` или `done` |
| `step` / `current` | Номер и описание текущего шага |
| `expected_action` | Единственное ожидаемое следующее действие |
| `paused` | Ортогональная пауза без потери этапа и шага |

`expected_action` не хранится отдельной изменяемой строкой. Оно детерминированно вычисляется из полного `TaskContext`, поэтому не может рассинхронизироваться с этапом:

- пустой `planning` → `define_plan`;
- готовый план → `start_execution`;
- текущий шаг → `complete_current_step`;
- все шаги выполнены → `start_validation`;
- проверка ещё не записана → `record_validation`;
- успешная проверка → `finish_task`;
- неуспешная проверка → `return_to_execution`;
- задача на паузе → `resume`;
- завершённая задача → `none`.

## Контролируемые переходы

`TaskStateMachine` запрещает:

- начать execution без плана;
- перейти к validation до завершения всех шагов;
- завершить задачу без успешной проверки;
- продолжать любые действия, пока задача на паузе;
- вернуться из validation до сохранения результата проверки;
- изменить terminal-состояние `done`.

Если validation завершилась с ошибкой, автомат возвращает последний шаг в execution на доработку.

## Пауза и продолжение

Пауза не является отдельным этапом. Она сохраняет текущие `state`, `step`, `current`, план и прогресс. Поэтому после `/task resume` автомат продолжает ровно с прежнего места.

При повторном запуске CLI сразу показывает восстановленные:

```text
stage
current step
expected action
paused
```

Тот же блок добавляется к каждому prompt. Пользователю достаточно написать «Продолжай» — повторять описание задачи и план не требуется.

## Запуск

```bash
pip install -r requirements.txt
python3 day-13-task-state-machine/main.py
```

Команды задачи:

| Команда | Действие |
|---|---|
| `/task create DESCRIPTION` | Создать задачу в planning |
| `/task plan STEP1 STEP2` | Сохранить план |
| `/task transition execution\|validation\|done` | Выполнить допустимый переход |
| `/task complete` | Завершить текущий шаг |
| `/task check pass\|fail RESULT` | Записать результат проверки |
| `/task pause` | Поставить задачу на паузу |
| `/task resume` | Продолжить без сброса контекста |
| `/task status` | Показать формальное состояние |
| `/context` | Посмотреть prompt, включая Task State |

Значения с пробелами заключайте в кавычки.

## Как проверить задание

### Автоматические тесты без API

```bash
python3 -m unittest discover -s day-13-task-state-machine -p "test_*.py" -v
```

Тесты проверяют:

- все этапы и соответствующие expected actions;
- запрет недопустимых переходов;
- паузу и resume в planning, execution и validation;
- запрет прогресса во время паузы;
- восстановление задачи новым экземпляром repository и agent;
- продолжение со второго шага без повторного описания;
- возврат последнего шага на доработку после failed validation;
- сохранение памяти и персонализации Дней 11–12.

### Ручной сценарий

```text
/task create "Подготовить навигационный модуль"
/task plan "Определить API" "Добавить тесты"
/task transition execution
/task complete
/task pause
/task status
/exit
```

Запустите программу снова, откройте тот же диалог:

```text
/task status
/context
/task resume
Продолжай.
```

Ожидаемый результат: восстановлены `execution`, шаг «Добавить тесты» и `expected_action=resume`; после resume ожидается `complete_current_step`. Описание задачи повторно не вводится.

### Эксперимент с Groq

```bash
python3 day-13-task-state-machine/experiment.py
```

Скрипт создаёт задачу, завершает первый шаг, ставит её на паузу, пересоздаёт repository и agent, затем отправляет только «Продолжай».

## Результат

Бублик получил формализованное, сохраняемое состояние задачи. Этап, текущий шаг и ожидаемое действие контролируются кодом; задачу можно остановить на любом незавершённом этапе и продолжить после перезапуска без повторных объяснений.
