# День 35 — AI-журнал разработки из локальной истории Git

Реальная задача: помочь владельцу Imperz / Discretat Nu составлять русский черновик журнала по изменениям документации, уже включённым в `main`. Сборщик сам читает Git, передаёт короткие diff-фрагменты локальному Qwen и сохраняет Markdown с источниками. Содержательное решение о приёмке принимает человек.

**Итоговый статус: Course Minimum PASS.** За 14.10.2026 (`Europe/Kyiv`) получен русский журнал по четырём подтверждённым merged PR. Настоящий Qwen2.5:14b Q4_K_M вернул HTTP 200; генерация заняла 201.941 с, весь успешный запуск — 204.529 с. Все детерминированные проверки и ручная проверка владельца Ly41k пройдены 17.10.2026. Исходный Imperz не изменён. Подтверждение основано на предоставленных владельцем выводах локальных `review` и `summary`; полный журнал и сырые доказательства остаются на Mac.

Всего было два настоящих локальных вызова: первый сформировал текст без URL и не прошёл проверку ссылок; после исправления инструкции формата второй прошёл все проверки. Первый ответ не редактировался. Код после успешной приёмки не менялся; в финальном пакете обновлены только документы и безопасный статус. [Итоговый отчёт](FINAL_REPORT.ru.md).

## Требования и границы

- Python 3.13 на Mac, Git, стандартная библиотека Python; `pip install` не нужен.
- GitHub CLI `gh` с уже настроенным доступом к `Ly41k/Imperz`; используются только REST GET для метаданных PR.
- Полный локальный checkout `Ly41k/Imperz`; `main` или локальная `origin/main` уже содержит необходимые merge/squash-коммиты.
- Ollama на `http://127.0.0.1:11434`, установленная `qwen2.5:14b` с `Q4_K_M`.
- Единственный сценарий: Git → ограниченный контекст → один POST `/api/chat` → Markdown → проверки → ручная приёмка.
- Нет облачных LLM, embeddings, автоматических публикаций или Git writes.

Модуль не подключает существующие адаптеры OpenAI/Groq из других дней. Проверка модели использует GET `/api/tags`, не генерацию. HTTP-прокси и перенаправления отключены; endpoint фиксирован на loopback. Нет автоматических повторов. Если Ollama не запущен, запустите его обычным способом на Mac. Модель автоматически не скачивается.

## Запуск на Mac

Распакуйте поставку в корень `ai-advent-llm-api`, чтобы здесь появилась папка `day-35-real-task/`. Команды ниже выполняются из корня курса. Вместо `/ABSOLUTE/PATH/Imperz` укажите существующий checkout игры.

```bash
python3.13 -m unittest discover -s day-35-real-task/tests -v
gh auth status
python3.13 day-35-real-task/main.py check-model
```

Далее один настоящий запуск за 14 октября:

```bash
python3.13 day-35-real-task/main.py run \
  --repo /ABSOLUTE/PATH/Imperz \
  --date 2026-10-14 \
  --ref main \
  --expect-pr 111 112 113 114 \
  --run-id day35-imperz-20261014-01
```

Если в активированном окружении `python --version` уже показывает 3.13, можно использовать `python` вместо `python3.13`.

Контрольные номера используются **только для проверки наличия в собранной истории**. Они не задают текст, заголовки или игровые механики. Сборщик включает все поддерживаемые merge-коммиты выбранного дня, включая дополнительные PR.

Результат по умолчанию сохраняется вне обоих репозиториев:

```text
~/day35-private/results/day35-imperz-20261014-01/
  development-journal.ru.md
  evidence.json
  acceptance.json
  generation.json
  ollama-request.json
  ollama-response.json
```

`run-id` нельзя перезаписывать. Если подтверждённых изменений нет, Markdown не создаётся, LLM не вызывается. Если не найден контрольный PR, программа останавливается до LLM. Для отдельного просмотра evidence без генерации есть `--collect-only` с другим `run-id`; для обязательного сценария он не нужен.

`--out` позволяет выбрать другой приватный каталог вне Imperz. Не направляйте его в публичный checkout курса: содержимое результатов приватное. Встроенная `.gitignore` — дополнительная защита только для результатов внутри модуля. Приложение не может предотвратить ручное копирование владельцем приватных файлов в другую папку.

## Какие даты и статусы подтверждает Git

Сборщик фиксирует SHA выбранной `main` и просматривает **первую линию родителей**. Через `gh api --method GET` он получает список closed PR в `main`, с пагинацией, и оставляет только метаданные: номер, `merged_at`, `merge_commit_sha`, base и канонический URL. Ни названия PR, ни PR body, ни удалённые diff не используются как источник содержания. Токен обрабатывает `gh`; приложение его не читает и не сохраняет.

Дата определяется **по GitHub `merged_at` в `Europe/Kyiv`**, не по авторской или committer-дате коммита. Для 14.10.2026 интервал составляет `[2026-10-13T21:00:00Z, 2026-10-14T21:00:00Z)`. SHA из метаданных должен реально присутствовать в первой линии локальной `main`. Diff считается между первым родителем и подтверждённым merge/squash-коммитом: это фактическое изменение `main`, включая разрешения конфликтов.

Поддерживаются двухродительские merge-коммиты `Merge pull request #N from ...` и однородительские squash-коммиты с суффиксом `(#N)` в заголовке, подтверждённые GitHub по SHA и `merged_at`. Closed без `merged_at` не считается выполненным. Несовпадение номера/SHA, отсутствие SHA в локальной `main` или неподдерживаемый rebase блокируют генерацию. Наличие четырёх контрольных PR проверяется явно; они не используются для выборки только этих четырёх PR.

**Область журнала — подтверждённые merged PR, а не полный перечень прямых коммитов.** Прочие коммиты с committer-датой этого дня записываются в evidence отдельно как кандидаты без подтверждённого времени включения (`unattributed_committer_date_candidates`). Они не передаются модели как выполненные изменения за дату. Поэтому наличие таких коммитов больше не блокирует корректные PR и не приводит к выдуманной дате публикации.

Это один локальный Git-сборщик с read-only проверкой метаданных PR, не второй способ загрузки содержимого репозитория. Он не делает fetch и не утверждает, что локальный ref совпадает с удалённой `main` в текущую секунду. Для подготовки нужен доступ к GitHub; после сохранения результатов `verify`, `review` и `summary` работают без сети. Все AI-запросы остаются локальными.

Работа идёт с Git-объектами, не текущими незакоммиченными текстами файлов. Приложение не меняет Imperz. До и после сбора/генерации сравниваются HEAD, refs, status и diff рабочего дерева; `GIT_OPTIONAL_LOCKS=0` исключает штатное обновление индекса командами чтения. Записи результатов внутрь Imperz запрещены. Во время запуска не меняйте исходный checkout другой программой.

## Контекст и локальная генерация

В контекст включаются SHA, PR, время merge, список изменённых путей и короткие фрагменты diff документации. Приоритет у русских документов, до восьми на событие. Объём diff распределён между всеми событиями; отброшенные символы/документы и SHA-256 полного diff фиксируются. Для модели сообщение коммита ограничено 800 символами, список путей — 24; метаданные аудита и хеши diff ей не нужны и остаются в evidence. Полный репозиторий и токены GitHub не читаются и не передаются модели.

Предел сериализованного контекста — 28 000 символов; превышение блокирует LLM-вызов. Суммарный бюджет diff — около 19 000 символов. Это ограниченный обзор, а не полное ревью каждой строки. Неопределённое содержание следует описывать как изменение документа, без догадок о правилах.

Ollama: `temperature=0`, `seed=35`, `num_ctx=16384`, `num_predict=2400`; таймаут по умолчанию 1200 секунд. Модель получает Git-данные как недоверенные, отдельным пользовательским сообщением, а правила — системным. Система не исполняет указания из diff и не даёт модели инструменты. Prompt прямо запрещает выдавать планы за правила, документацию за движок и пересказывать численные MK-характеристики. Это снижает риск, но смысл всё равно проверяет человек.

Ответ модели сохраняется **без редакторского переписывания**. Полный локальный запрос и исходные байты ответа сохраняются для проверки. `generation.json` содержит HTTP status, имя и digest модели, квантование, wall time, число генераций, хеши запроса/ответа и доступные метрики Ollama (duration в наносекундах). Ответ с `done_reason=length` не принимается.

В версии v4 после JSON добавлена явная инструкция формата: каркас Markdown с полными каноническими ссылками всех собранных PR. Каркас не содержит готового описания механик; содержательный текст и итоговый Markdown формирует Qwen. Приложение не дописывает ссылки после ответа модели. В `generation.json` записывается `prompt_version=2`. Исторические запросы v3 из двух сообщений (`prompt_version` отсутствует) по-прежнему проверяются по исходному формату, без изменения сохранённого ответа.

## Приёмка

После успешного запуска ожидаются:

- `technical=PASS`: есть изменения, ссылки/PR/SHA допустимы, все события процитированы, источник не изменён.
- `ai_generation_evidence=PASS`: сохранён ответ HTTP 200 от loopback, модель завершила ответ, текст в Markdown точно совпадает с ответом, запрос связан с evidence.
- `ai=PENDING_OR_FAIL`, `course_minimum=PENDING_OR_FAIL`: ещё нужна содержательная проверка.

Детерминированная проверка не обращается к ссылкам по сети: она разрешает только канонические URL подтверждённых merge-коммитов и PR из evidence. Проверяются все упомянутые PR и SHA; ссылки вне allowlist, ссылки на локальные файлы, Markdown reference links и HTML anchors запрещены. Каждый содержательный абзац/пункт должен содержать ссылку на той же строке. Проверяются дата, три раздела и покрытие событий. Эти проверки не доказывают смысловую истинность каждого утверждения.

Откройте Markdown и сравните его с `evidence.json` и соответствующими Git diff. Владелец должен проверить:

1. Дату, список событий и соответствие каждому контрольному PR.
2. Каждое утверждение по его источнику, особенно при обрезанном контексте.
3. Отсутствие выдуманных механик и изменённых численных параметров.
4. Разделение утверждённых спецификаций, черновиков и Future Plans.
5. Отсутствие заявления об реализации игрового движка или завершении несмерженной работы.

После **фактически выполненной** проверки владелец может записать приёмку:

```bash
python3.13 day-35-real-task/main.py review \
  "$HOME/day35-private/results/day35-imperz-20261014-01" \
  --reviewer Ly41k --approve \
  --notes "Сопоставлены все утверждения и контрольные PR; механики не выдуманы, планы отделены от правил."
```

Команда `review` записывает заявление владельца о выполненной проверке; сама она не оценивает смысл. Хеши проверенных файлов привязаны к приёмке. Любая последующая правка результата сбрасывает ручную приёмку. Редакторски изменённый Markdown не считается исходным ответом модели. Не заменяйте сырой ответ исправленным текстом.

Повторная проверка без сети и без Qwen:

```bash
python3.13 day-35-real-task/main.py verify \
  "$HOME/day35-private/results/day35-imperz-20261014-01"
```

Для передачи безопасной сводки без закрытых текстов, путей и SHA источника:

```bash
python3.13 day-35-real-task/main.py summary \
  "$HOME/day35-private/results/day35-imperz-20261014-01"
```

Если обнаружена содержательная ошибка, сохраните первый запуск, исправьте причину и используйте второй `run-id` для единственного разрешённого повторного локального запуска. Не добивайтесь идеального стиля серией запросов. Ошибка ссылок тоже сохраняет ответ и диагностику; повторных запросов автоматически нет.

Файлы аудита являются локальными доказательствами для владельца, не криптографической аттестацией HTTP или личности рецензента. Offline tests используют временные синтетические данные и подмену HTTP в тестовом процессе; они никогда не публикуются как реальный запуск.
