## Что меняется

Флаг `--quality-mode coverage` включает новый prompt: модель должна охватить разные части вопроса, выбрать доказательства из соответствующих разделов, назвать исходные технические этапы, сохранить отрицания, необязательность и область действия требований. При равнозначных переводах предпочитается язык вопроса, но важное доказательство на другом языке не исключается. Прямое описание механизма предпочтительнее общих итогов и тестов.

Это общие правила ответа. Идентификаторы контрольных вопросов, ожидаемые ответы, expected_terms, expected_sources и эталонная рубрика модели не передаются. Нет заранее написанных ответов, автоматического ремонта, дополнительных скрытых вызовов или подстановки терминов приложением. Рубрики и исходные questions JSON не меняются.

Режим по умолчанию `baseline` сохраняет прежние prompts V12, в том числе второй этап. Новый режим совместим с `--synthesis`, но для первой пробы synthesis выключен: один вызов на вопрос. Retrieval, индекс, embeddings, модель и лимит ответа не меняются. Меняются только файлы Day 28.

## Первая проба — два вопроса, по одному ответу

Сохрани `reports/check/openai-small-v12.json`. В архиве есть его исходная побайтовая копия на случай удаления старого файла. Выполняй команды из корня проекта; существующий OPENAI_API_KEY используется из окружения или корневого `.env`.

```bash
python day-28-local-rag/main.py compare \
  --cloud-provider openai --only-provider cloud \
  --quality-mode coverage \
  --questions day-28-local-rag/questions-openai-small.json \
  --retry-from day-28-local-rag/reports/check/openai-small-v12.json \
  --repeats 1 --max-tokens 1000 --cloud-rate-retries 0 \
  --output day-28-local-rag/reports/check/openai-quality-probe-v13.json

python day-28-local-rag/verify_report.py \
  day-28-local-rag/reports/check/openai-quality-probe-v13.json
```

План: только cloud/base-03 и cloud/base-10, по одному наблюдению и вызову генерации. rewrite-ru-02 (3/3 V12) сохраняется и повторно не запускается. Локальная генерация не вызывается; локальные embeddings и поиск нужны. Помимо двух POST генерации есть диагностические запросы модели/сервера; это не дополнительные генерации.

Для просмотра плана без HTTP/embedding/generation добавь `--plan-only` к первой команде. Ожидается generation_upper_bound: local=0, cloud=2; retained_case_provider_pairs=1. План не создаёт новый отчёт.

Если повторять исправления, используй новую версию кода и неуспешный probe как `--retry-from`, новое имя output и всё ещё `--repeats 1`. Успешные пары будут сохранены. При полном успехе retry от probe будет пустым: это сохранение результата, а не проверка стабильности.

Три повтора и полный набор сейчас не запускаем. Если финальная проверка понадобится, её надо запланировать отдельно с явным объёмом и едиными настройками. Успешная одиночная проба подтверждает только ответ на этой пробе, а не стабильность и не полный новый benchmark.

## Что проверять после запуска

- base-03: ответ различает Preflight до основной генерации и Postflight после неё/до сохранения; обе части подтверждены выбранными цитатами. Одного упоминания терминов недостаточно.
- base-10: точные команды systemctl/journalctl, расписание и общая БД, наблюдаемые логи/свежие сохранённые сводки. Если упомянут GITHUB_TOKEN, сохранено, что для публичных репозиториев он необязателен и помогает с лимитами. Инструкция не является доказательством реального развёртывания на VPS.
- Автоматический pass требует исходных терминов/источников. Если выбран только английский README, исходная рубрика всё ещё может не пройти. Этот результат не переписываем: отдельно отмечаем корректность смысла и ограничение рубрики.
- Нужен ручной просмотр фактической поддержки каждой части ответа: verifier проверяет внутреннюю согласованность и точность цитат, а не семантическое следование.

Ориентир расходов первой пробы на той же модели — около $0.005–0.01, в зависимости от usage. Это оценка без гарантии счёта; локальные вызовы не используют платный API. Полная перепроверка всех 20 вопросов не входит в этот запуск.
