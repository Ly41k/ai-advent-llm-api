# V3 — исправления по compare-v2.json

Пользовательский V2 прогон завершился: local 60/60 валидных результатов, 48/60 эвристических pass; cloud 48/60 валидных, 8 превышений лимита quote_ids и 4 HTTP 429. Эти исходные результаты не менялись.

Изменены только файлы Day 28. Индекс Недели 6 остаётся прежним.

- `--retry-from` проверяет внутреннюю согласованность baseline и выбирает только проблемные пары вопрос–провайдер. Успешная local-пара не вызывается из-за cloud-ошибки. `--plan-only` не обращается к моделям.
- Прежние валидные ответы переоцениваются текущими критериями без генерации; изменения критериев и оценок записаны явно. Невалидные raw ответы не исправляются и не засчитываются.
- Корректный VPS ответ проверяется по systemctl/journalctl. Допускается цитирование соответствующего client.py или README другого языка того же дня. Для изоляции диалогов нужны SQLite и термин идентичности.
- Prompt требует объяснения механизма и всех частей вопроса, прямых доказательств, обычно 1–4 IDs и максимум 12.
- GPT-OSS получает Groq strict JSON Schema с допустимыми IDs. Контракт и исходные цитаты дополнительно проверяются приложением. Silent fallback и repair-вызовов нет.
- HTTP 429 получает не более двух повторов после 30/60 секунд; попытки и ожидания сохранены. При сохранении 429 cloud приостанавливается до конца прогона с явными ошибками, local продолжает работу. Дневную квоту это не отменяет.
- Новые отчёты помечены selective_retry, метрики относятся только к новым наблюдениям. Исторические результаты не смешиваются в новый полный benchmark.

План на пользовательском отчёте: local base-01/base-03/rewrite-ru-02 × 3 = **9 вызовов**; cloud 7 вопросов × 3 = **21 вызов максимум**, плюс ограниченные транспортные повторы при 429. Повторы у пары нужны для новой оценки стабильности; успешные пары вне плана сохраняются в исходных отчётах.

Проверено: **105 offline-тестов** (Day 28: 39; Day 21: 7; Day 23: 21; Day 26: 38), compileall, diff --check. В том числе: исключение успешной local-модели, baseline без изменений, cloud-only retry, отсутствие ключа, прерывание, запрет перезаписи baseline, ограничение/пауза HTTP 429, сохранение диагностики, strict schema, 8 реальных невалидных cloud-ответов остаются невалидными.

`ask-v2.json` проходит verifier. `compare-v2.json` внутренне согласован, но остаётся неуспешным полным прогоном по прежним критериям. План проверен без новых запросов к LLM. V3 live-генерация на Mac ещё нужна; улучшение полноты ответа нельзя подтвердить только offline-тестами.

Следующий шаг: команды выборочного прогона в README.ru.md. Полный повтор 20 × 3 отложен по указанию пользователя. Демонстрация запуска без интернет-соединения также ещё не выполнена в этой среде.
