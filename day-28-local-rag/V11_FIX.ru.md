В V11 доступен явный режим `--synthesis`:

1. Локальный retrieval по прежнему индексу Недели 6.
2. Первый вызов модели по общему каталогу выбирает доказательства в формате evidence_claims_v8. Сформулированные в этом вызове statements сохраняются для диагностики, но не публикуются как финальный ответ и не становятся фактами для второго вызова.
3. Приложение берёт только выбранные quote_ids и соответствующие точные исходные цитаты. Отбрасывает остальные фрагменты и дубли IDs. Тексты цитат не переписываются.
4. Второй вызов той же модели получает вопрос и только эти доказательства. Модель формулирует цельный answer и выбирает поддерживающие IDs в формате quote_slots_v4.
5. Приложение проверяет финальные IDs по выбранному подкаталогу и подставляет исходные цитаты. ID из невыбранного фрагмента отклоняется, даже если он был в первоначальном retrieval. Качество оценивается у финального ответа по прежнему rubric.

Это два открыто учитываемых вызова, а не скрытый ремонт после проверки эталона. В prompt второго этапа не передаются expected_terms, эталонный ответ, оценки первого ответа или требуемое название SQLite. Он просит объяснить документированное хранилище, восстановление и изоляцию. Если первый этап отказывается, второй не вызывается. При пустом retrieval выполняется прежний отказ без модели. Ошибка/невалидный ответ/незавершённая генерация любого этапа не становится успешным результатом.

На выборе доказательств из реального V10 пользовательское сообщение второго этапа содержит 2287 символов вместо 16458 первоначального. В нём есть SQLite, загрузка completed сообщений и conversation_id. Это проверка подготовки контекста, не live-подтверждение улучшения модели. Первый этап остаётся прежним; суммарная скорость может снизиться из-за дополнительного вызова.

Отчёты schema_version=11, synthesis_mode=true, prompt_revision=selection_then_synthesis_v11 сохраняют selection_generation, selection_response, synthesis (сообщения, hash и подкаталог), generation финального вызова и generation_calls. Время generation_wall_seconds включает оба этапа и подготовку между ними; pipeline_seconds также включает retrieval. Сводка attempts считает пробы, generation_calls — логические вызовы generate. HTTP-повторы cloud 429 отдельно видны в transport_attempts и тоже входят в wall time; они могут увеличить число сетевых запросов сверх двух.

Verifier пересобирает второй prompt из raw выбора и первоначального каталога, проверяет оба model/provider, полноту генерации, raw/parsed ответы, hash/сообщения/подкаталог, финальные цитаты, метрики и число этапов. Структурные проверки не доказывают смысловую поддержку; после live-запуска нужен ручной просмотр утверждений и цитат.

При сравнении двух моделей общий retrieval и первый prompt совпадают для парных проб; выбранные провайдерами доказательства могут различаться, поэтому второй prompt может быть разным. Это сравнение двух этапов RAG, его нельзя выдавать за генерацию по идентичному второму контексту. Исторический одновызовный benchmark и новые выборочные измерения не объединяются. Без --synthesis остаётся прежний режим одного вызова.
