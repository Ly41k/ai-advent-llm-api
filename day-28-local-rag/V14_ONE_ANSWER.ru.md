## Изменение V14

`--quality-mode complete` генерирует answer + четыре nullable quote IDs непосредственно по полному retrieved quotation catalog за один вызов. Схема quote_slots_v4 уже поддерживается проектом. Приложение проверяет IDs, точные цитаты и отсутствие повторных IDs; текст ответа остаётся модельным. Нет подстановки готовых ответов и дополнительных вызовов для ремонта.

Prompt просит цельное покрытие вопроса вместо четырёх независимых claims. Для проверок вокруг операции явно охватываются проверки до и после; исходные названия и факты берутся из разделов источника. Приложение не выбирает заранее правильные Preflight/Postflight и не получает expected_terms/expected_sources в generation. Общие правила сохраняют отрицания, необязательность и область действия требований.

Весь retrieved context доступен единственному вызову, а не только уже выбранный Postflight. `--synthesis` в complete запрещён до любых обращений к индексу/провайдерам, чтобы не возник второй вызов. Baseline и исторический coverage V13 сохранены; их prompts и проверка старых JSON не меняются. Индекс, retrieval, модель и API не меняются.

## Следующая проба — только base-03, один вызов

Оставь исходный `openai-quality-probe-v13.json`; его побайтовая копия есть в архиве. Выполняй из корня проекта:

```bash
python day-28-local-rag/main.py compare \
  --cloud-provider openai --only-provider cloud \
  --quality-mode complete \
  --questions day-28-local-rag/questions-openai-small.json \
  --retry-from day-28-local-rag/reports/check/openai-quality-probe-v13.json \
  --repeats 1 --max-tokens 1000 --cloud-rate-retries 0 \
  --output day-28-local-rag/reports/check/openai-quality-probe-v14.json

python day-28-local-rag/verify_report.py \
  day-28-local-rag/reports/check/openai-quality-probe-v14.json
```

Ожидаемый план: generation_upper_bound local=0/cloud=1; rerun cloud/base-03; retained cloud/base-10. rewrite-ru-02 уже сохранён в V12 и не входит в V13 subset; он также не запускается. Для просмотра без HTTP/inference добавь --plan-only к первой команде.

После запуска нужен ручной просмотр: Preflight до основной генерации с локальной и семантической проверкой запроса, Postflight после генерации/до сохранения с проверкой ответа; обе фазы и их факты поддержаны цитатами. Упоминания терминов без механизма недостаточно. Если ответ не пройдёт, следующий выборочный retry остаётся по одному повтору. Если пройдёт, это успешная одиночная проба, не доказательство стабильности и не полный свежий benchmark.

Ориентир расходов — несколько тысячных доллара. Сейчас три повтора и полный прогон не выполняем. Финальный benchmark можно отдельно запланировать после проверки этой пробы.
