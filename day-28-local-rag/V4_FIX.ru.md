# V4 — разбор retry-v3 и исправления

Исходный retry-v3 остаётся неизменным: local 9/9 валидных результатов, 3/9 эвристических pass. base-01 прошёл во всех трёх повторах и исключён из следующих вызовов. base-03 пропустил preflight в ответе; rewrite-ru-02 описал механизм, но выбрал слабые цитаты из EN README.

Cloud: один HTTP 400, затем три HTTP 429 с ожиданиями 30/60 секунд. Остальные 19 наблюдений — пропуск после остановки cloud, а не 19 дополнительных HTTP-вызовов. Независимый verifier не принимает весь retry-v3; отдельная проверка внутренней согласованности проходит. Причина HTTP 400 в сохранённой безопасной диагностике не раскрыта. Доказать по этому отчёту, что отказ связан именно с maxItems/enum, нельзя.

Изменены только файлы Day 28:

- Целые абзацы и блоки кода вместо каталога отдельных строк. Сохранены точные подстроки, standalone headings/fences не предлагаются как доказательства.
- Четыре обязательных nullable слота q1–q4 вместо массива quote_ids. Простой closed-object контракт без maxItems, максимум четыре доказательства; неизвестные IDs, дубли, лишние ключи, неправильные типы и неправильные отказы отклоняются. Смысл цитат всё ещё требует проверки человеком.
- Prompt явно просит две части BEFORE/AFTER для проверок вокруг генерации, с документированными техническими именами.
- RU вопрос Day 7 может цитировать соответствующий EN README, но лексическая проверка требует SQLite и термин идентичности в самих выбранных цитатах. Слабая исходная выборка не засчитана задним числом.
- --only-provider local|cloud позволяет проверять cloud отдельно; evaluate всегда полностью local и не читает cloud key.
- V4 отчёты сохраняют новую схему/catalog style; verifier проверяет V2/V3 по их прежним контрактам. Замороженные успехи остаются историческими, не выдаются за полный V4 benchmark.

План от retry-v3: **6 local вызовов**, base-03/rewrite-ru-02 по три; облако можно временно не вызывать. Позже отдельный cloud-only план содержит 21 запланированный вызов максимум и прежнюю ограниченную обработку 429.

Проверены 44 offline-теста Day 28, compileall и diff --check. В частности: точность целых passages и кода, отсутствие массивных ограничений в JSON Schema, nullable слоты/форма/дубли/IDs/refusal, weak evidence не проходит из-за разрешения EN источника, фильтр cloud-only не вызывает pending local. Повторный план и внутренние проверки выполнены на реальном retry-v3 без HTTP или generation. Сокращение entries каталога: base-03 147→42, rewrite-ru-02 305→90; это не измерение качества/скорости модели.

Live V4 ещё не выполнен. Совместимость новой схемы с реальным Groq API и полнота ответов Qwen остаются предметом следующего выборочного прогона. Изменения корпуса Недели 6 и переиндексация не нужны.
