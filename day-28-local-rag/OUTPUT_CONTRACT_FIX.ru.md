# V2: исправление контракта первого live-ответа

Причина: HTTP-клиент Day 26 предназначен для обычного текста. В Day 28 v1 JSON и копирование цитат задавались только prompt-инструкцией. Реальный Qwen-ответ завершился `}"` и убрал backticks вокруг `worker.py`; проверка правильно отклонила его.

Исправление:

1. Локальный HTTP-адаптер Day 28 добавляет Ollama JSON Schema с допустимыми quotation IDs. Предыдущие дни не изменены.
2. Groq получает JSON object mode с последующей проверкой контракта приложением. Разница output controls видна в отчёте; сообщения/контекст модели идентичны.
3. Модель выбирает IDs, приложение подставляет исходные цитаты. Нет fuzzy matching, удаления лишних символов, скрытого второго LLM-вызова или принятия выдуманного ID.
4. Старый failed report не превращается в успешный: нужны новый raw response и новый live-отчёт.

Тесты воспроизводят исходную ошибку из предоставленного ask.json; дополнительно проверены API request body, exact quotes с backticks, indentation и ошибочные IDs.

Остальные свойства сохранены: read-only индекс Недели 6, локальные embeddings/search/generation, порог, final K, отказ без генерации при пустом контексте, paired prompts, статистика и строгая проверка отчётов.

После обновления существующий валидный индекс не требует пересборки: root README и корпус дней 1–20 этим исправлением не меняются.
