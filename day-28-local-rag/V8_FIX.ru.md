V8 меняет каталог доказательств. Markdown-раздел сохраняется вместе с заголовком, прозой и кодом, как точная непрерывная подстрока исходного чанка. Заголовки внутри fenced code не разбивают раздел. Длинные разделы группируются по исходным абзацам с мягкой границей 2400 символов; отдельный длинный абзац сохраняется целиком. Текст не переписывается, предложения из разных мест не склеиваются, правильный ответ из эталона не добавляется.

Это сохраняет документированный контекст механизма. Например, исходный раздел «Как это работает» описывает открытие SQLite, выбор темы, загрузку завершённых сообщений, UUID/conversation_id, изолированный запрос и сохранение полной истории. У модели теперь есть один цельный фрагмент с этими шагами. Это доступное доказательство, а не обещание, что модель выберет именно его.

Контекст передаётся объектами `quote_id`/`quote`, а не одной строкой с маркерами. Native schema берёт enum IDs из этих объектов. Контракт утверждений остаётся из четырёх nullable слотов; V8 разрешает использовать один ID в разных утверждениях, если тот же раздел подтверждает каждое. Цитата сохраняется рядом с каждым утверждением в исходном порядке. Неизвестные IDs, неверная форма, пустые утверждения, отдельный answer и ложный отказ по-прежнему отклоняются. Прежний V7 сохраняет своё правило отклонения повторных IDs при проверке исторических отчётов.

На реальном контексте этого вопроса каталог сокращается с 90 до 40 записей. JSON-контекст увеличивается с 14684 до 16372 символов из-за заголовков, fences и структуры объектов. Сокращение числа IDs не доказывает ускорения модели; скорость и качество требуют нового live-запуска. max_context_chars по-прежнему ограничивает исходные выбранные чанки до форматирования, а num_ctx задаёт контекст модели.

Отчёт: schema_version=8, prompt_revision=json_sections_v8, output_contract=evidence_claims_v8, quote_catalog_style=sections_v8, model_context_style=objects_v8. Verifier независимо пересобирает каталог/контекст из сохранённых исходников и утверждения/цитаты из raw JSON. Исторические V2–V7 форматы сохраняются без ремонта ответов и изменения результатов. Retrieval, индекс Недели 6, другие дни не меняются; переиндексация не нужна.
