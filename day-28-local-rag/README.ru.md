# День 28 — Локальная LLM + RAG

Бублик использует **SQLite-индекс Недели 6 / Дня 21**, локально вычисляет embedding вопроса и находит доказательства, затем генерирует ответ через скачанную модель Ollama. Облачная генерация — дополнительное сравнение. Локальные `ask` и `evaluate` после подготовки не требуют облачных ключей или интернета.

Реализация и живая оценка завершены. В репозитории сохранены исходное парное сравнение, выборочные исправления, проверка локальной стабильности и отдельная проверка качества/стабильности OpenAI. Это разные прогоны со своими версиями и настройками; они не объединяются в новый полный benchmark.

## Пайплайн

Вопрос → эвристическое расширение запроса → локальный embedding bge-m3 → SQLite cosine search → фильтрация релевантности → final top-K и бюджет контекста → локальная Qwen → проверенный формат ответа и точные цитаты источников.

Переиспользуются storage Дня 21, retrieval/filter Дня 23 и HTTP-клиенты Дня 26. Индекс открыт только для чтения. Локальный HTTP ограничен loopback-адресами; перехода на облако при ошибке нет. Ожидаемые ответы и термины оценочной рубрики не передаются генерации.

## Быстрый запуск

Из корня репозитория в существующем окружении Python 3.13:

```bash
python -m pip install -r day-28-local-rag/requirements.txt
ollama pull bge-m3
ollama pull qwen2.5:14b
```

Оставь Ollama запущенной через приложение или `ollama serve`. Интернет нужен для скачивания; дальнейший локальный запрос работает без него. Embedding-модель должна совпадать с индексом. Через `--local-model` можно выбрать другую скачанную локальную модель, но её результаты требуют отдельной оценки.

Используется `day-21-document-indexing/knowledge.db`. Если индекса нет или его корпус изменился:

```bash
python day-21-document-indexing/main.py build
python day-21-document-indexing/main.py verify
```

Корпус содержит корневые README, README дней 1–20 и Python-код дней 16–20 без тестов. Документация и вопросы Day 28 в него не входят. **Замена корневых README меняет индексируемые документы: перед следующим живым RAG-запросом пересобери индекс.** Изменение только файлов Day 28 не требует переиндексации. Сам Git-коммит при неизменном корпусе допускается проверкой digests/fingerprint Дня 28.

Проверь готовность и выполни один запрос:

```bash
python day-28-local-rag/main.py doctor
python day-28-local-rag/main.py ask \
  "Какой процесс выполняет фоновые задания на Day 18?" \
  --repeats 1 --max-tokens 512 \
  --output day-28-local-rag/reports/check/video-local.json
python day-28-local-rag/verify_report.py \
  day-28-local-rag/reports/check/video-local.json
```

`doctor` проверяет готовность без генерации ответа, поэтому ноль попыток и `local_rag_verified=false` в нём нормальны. После успешного локального ответа ожидаются `status=ok`, `local_model_loaded=true` и `local_rag_verified=true`. Последний флаг требует успешной подготовки, валидной RAG-генерации и подтверждения загрузки через Ollama `/api/ps`; смысловую правильность он не гарантирует.

Для демонстрации без интернета сначала подготовь модели/индекс, отключи интернет и выполни один `ask`. Сервис Ollama должен оставаться доступным. JSON сохраняет локальные адреса и признаки генерации, но сам по себе не удостоверяет отключение Wi-Fi.

## Ответы и доказательства

Режим `baseline` по умолчанию возвращает до четырёх утверждений `statement`/`quote_id`. Приложение соединяет модельные утверждения и подставляет точные цитаты и метаданные из найденных чанков. Один фрагмент может подтверждать несколько утверждений, поэтому повторные цитаты в этом контракте допустимы. Неизвестные IDs, неправильный формат и незавершённая генерация отклоняются. Исходный вывод модели сохраняется в `generation.answer` для диагностики.

Точные цитаты подтверждают происхождение, но не доказывают поддержку и полноту всех утверждений. Сравнивай ответ с выбранными фрагментами. Пользовательский `ask` не имеет заранее заданной эвристической рубрики и также требует ручного просмотра.

Если после retrieval нет подходящих доказательств, приложение возвращает отказ без вызова модели ответа. Отказ модели при непустом контексте должен соответствовать контракту. Только отказы приложения не подтверждают локальную генерацию.

## Сравнение с облаком

`compare` явно включает облачную генерацию. По умолчанию провайдер `groq` (`GROQ_API_KEY`, модель `openai/gpt-oss-20b`). OpenAI использует `OPENAI_API_KEY`, в том числе из существующего корневого `.env`, и закреплённую модель `gpt-4.1-mini-2025-04-14` по умолчанию. Локальные команды эти ключи не загружают. OpenAI SDK не требуется.

Необязательные парные сравнения:

```bash
python day-28-local-rag/main.py compare --repeats 3 \
  --output day-28-local-rag/reports/check/compare-groq.json
python day-28-local-rag/main.py compare --cloud-provider openai --repeats 3 \
  --output day-28-local-rag/reports/check/compare-openai.json
```

В новой паре retrieval и первый prompt одинаковы; порядок local/cloud чередуется между повторами. При `--synthesis` модели отдельно выбирают доказательства, поэтому второй контекст может различаться. Cloud-only и выборочные прогоны — отдельные измерения, а не новые пары с историческими локальными ответами. Сравнение передаёт найденные фрагменты выбранному облачному провайдеру.

Без ключа обычное сравнение явно фиксирует пропуск облака и продолжает локально. Ошибки подготовки/API/формата/качества сохраняются. Для HTTP 429 предусмотрены ограниченные повторы; после исчерпания оставшиеся cloud-наблюдения могут быть пропущены, local продолжает работу. `--cloud-rate-retries 0` отключает транспортные повторы. Скрытых генераций для ремонта ответа нет.

## Режимы качества и количество вызовов

| Режим | Поведение | Вызовов ответа на фактическую пробу |
|---|---|---:|
| `baseline` (по умолчанию) | Утверждения с доказательствами; сохранённый локальный профиль | 1 |
| `coverage` | Утверждения с усиленной инструкцией полноты составного вопроса | 1 |
| `complete` | Один цельный ответ с IDs подтверждающих цитат | 1 |
| `phases` | Обязательные before/after с разными IDs доказательств | 1 |
| `baseline` или `coverage` с `--synthesis` | Выбор доказательств, затем синтез по выбранным исходным цитатам | 2 |

`complete` и `phases` несовместимы с `--synthesis`. `phases` специализирован для вопросов о проверках до/после; не используй его для всего смешанного набора из 20 вопросов. Пустой retrieval требует ноль вызовов ответа. После отказа на этапе выбора доказательств синтез не вызывается. Транспортные повторы учитываются отдельно.

## Оценка и выборочные повторы

По умолчанию набор содержит 20 RU/EN вопросов, включая четыре отрицательных контроля. Новый полный прогон необязателен и может занять значительное время:

```bash
python day-28-local-rag/main.py evaluate --repeats 3 \
  --output day-28-local-rag/reports/check/local-new.json
```

Для сохранения успешных групп вопрос–провайдер используй существующий baseline и сначала посмотри план:

```bash
python day-28-local-rag/main.py evaluate \
  --retry-from day-28-local-rag/reports/accepted/compare-v2.json \
  --repeats 1 --plan-only \
  --output day-28-local-rag/reports/check/local-retry-plan.json
```

Убирай `--plan-only`, только если хочешь вызвать оставшиеся вопросы. Сам план не делает HTTP/embedding/generation-вызовов. Baseline проверяется и переоценивается текущей рубрикой без inference; неуспешные/отсутствующие группы повторяются, успешные сохраняются. Исходный файл не меняется. Для retry нужны совместимые вопросы, модели и параметры retrieval; изменение корпуса/настроек может потребовать отдельного нового прогона. Отчёт retry содержит только новые наблюдения. Retry от полностью успешной пробы может ничего не вызвать даже с `--repeats 3`; для стабильности нужен свежий узкий набор вопросов.

Последняя выборочная облачная проверка уже завершена; для сдачи повторять её не требуется. Если намеренно воспроизводишь только этот вопрос:

```bash
python day-28-local-rag/main.py compare \
  --cloud-provider openai --only-provider cloud --quality-mode phases \
  --questions day-28-local-rag/questions-invariants-only.json \
  --repeats 3 --max-tokens 1000 --cloud-rate-retries 0 \
  --output day-28-local-rag/reports/check/openai-phases-new.json
```

## Зафиксированные результаты

Живые отчёты используют Python 3.13.3, Ollama 0.34.4, локальные bge-m3 и Qwen 14B. Компьютер автора — MacBook Pro M1 с 32 GB RAM. В исходном индексе 120 fixed / 594 structural чанка, размерность 1024; после пересборки число чанков и revision могут отличаться.

| Прогон | Объём | Валидность / эвристическое качество | Медиана генерации | Точная стабильность ответа |
|---|---|---|---:|---|
| V2 local | 20 вопросов ×3, пара с Groq | 60/60 валидных; качество 48/60 | 54,53 с | 20/20 учитываемых групп |
| V2 Groq | Тот же исходный парный набор | 48/60 валидных; качество 38/48 | 0,82 с | 11/14 учитываемых групп |
| V11 local synthesis | Один исправленный вопрос об изоляции ×3, два вызова на пробу | 3/3 валидность и качество; ручная проверка пройдена | 43,03 с, оба этапа | 1/1 группы |
| V12 OpenAI baseline | Три вопроса ×3, только cloud | 9/9 валидных; качество 5/9 | 2,94 с | 0/3 групп |
| V16 OpenAI phases | Один исправленный вопрос об инвариантах ×3, только cloud | 3/3 валидность, качество и ручной просмотр | 2,84 с | 0/1 группы; цитаты одинаковые |
| Опубликованный video-local | Один пользовательский local-вопрос, один вызов | 1/1 валидный; поддержка просмотрена вручную, эвристической рубрики нет | 20,03 с | Не измерена |

Валидность V2 включает по девять отказов приложения на каждого провайдера; они исключены из скорости генерации. Стабильность не учитывает группы с невалидными/неуспешными пробами, но повторяющийся плохой ответ всё равно может быть дословно стабильным. Исходная оценка V2 остаётся исторической и не переписывается последующими исправлениями.

В V16 формулировки различаются, но обе фазы и цитаты согласованы во всех трёх ручных просмотрах. Медиана pipeline 2,91 с; интерполированный p95 генерации 3,25 с по трём наблюдениям. Опубликованный video-local занимает 21,40 с целиком. Это не новое парное сравнение скорости с двухэтапным local V11. Сам JSON не доказывает физическое отключение интернета.

Успешные VPS V13 и изоляция V12 сохраняются отдельно; исправление инвариантов подтверждено в V16. Исторические успехи разных режимов/версий не являются новым общим результатом всего набора или гарантией будущего качества.

## Отчёты и перепроверка

| Каталог | Назначение |
|---|---|
| `reports/check/` | Рабочие JSON/Markdown, checkpoints и эксперименты; игнорируется Git |
| `reports/video/` | Локальные материалы записи; игнорируется Git |
| `reports/accepted/` | Отобранные исходные live JSON, сохранённые в Git |
| `reports/verified/` | Аудиты, хеши и зафиксированные проверки реализации |

При обновлении не удаляй свои отчёты. Новые прогоны сохраняй под новыми именами. Исторические отчёты описывают корпус/prompts своего запуска и не меняются после переиндексации.

Перепроверка сохранённых результатов без вызовов моделей:

```bash
python day-28-local-rag/verify_report.py \
  day-28-local-rag/reports/accepted/local-stability-v11.json
python day-28-local-rag/verify_report.py \
  day-28-local-rag/reports/accepted/openai-quality-stability-v16.json
python day-28-local-rag/verify_report.py \
  day-28-local-rag/reports/accepted/video-local.json
```

Strict verifier проверяет внутреннюю согласованность, контракт, точные привязки, записанные метрики и эвристическое качество. Он не доказывает подлинность отчёта или смысловую правильность. Исторические прогоны с ошибками качества могут не пройти strict acceptance при корректной внутренней структуре. Скорость исключает отказы приложения и неуспешные генерации; generation wall включает транспортные повторы/ожидания. Exact stability сравнивает итоговые текст/цитаты, а не эквивалентность смысла.

Exit codes: `0` — принятый прогон/готовность, `1` — ошибка подготовки/транспорта/контракта/качества, `130` — прерывание. Отчёты пишутся атомарно с checkpoints после наблюдений.

Offline-тесты реализации (71 пройден на проверенном коде V16):

```bash
python -m unittest discover -s day-28-local-rag -p 'test*28.py'
```

Retrieval по умолчанию: fixed, candidate-K 20, final-K 5, raw cosine ≥0,50, heuristic rewrite, бюджет контекста 16000 символов. Локальный контекст 16384 токена; максимум вывода 2048; timeout 180 с. `ask` использует одну пробу; `evaluate`/`compare` — три. Температура обоих провайдеров 0; это не гарантирует дословно одинаковые ответы.
