# День 29 — оптимизация локальной LLM под RAG-задачу

Итог: Qwen2.5 14B Instruct Q4_K_M через локальную Ollama на MacBook Pro M1,
32 GB. Локальные bge-m3, индекс Дня 21 и retrieval. Temperature=0,
max_tokens=1024, num_ctx=8192. Новых запусков для завершения задания не нужно.

Подтверждённая область: короткая справка по репозиторию и отказ без доказательств
(12/12 наблюдений), плюс проверка периодического worker Дня 18 на VPS
(3/3 контрольных и 6/6 на двух новых формулировках RU/EN).
Всего семь вопросов и 21 содержательно проверенное наблюдение выбранного профиля.
Это небольшая выборка внутри конкретной задачи.

Справочные ответы используют V3. Периодическая процедура использует V7:

Question → local retrieval → exact role evidence → local Qwen selections →
validation → application-rendered procedure → separate semantic review

Модель выбирает четыре доказательства: состояние, журнал, результат выполнения
и повторное сохранение результатов относительно расписания. Приложение
собирает план из точных цитат и общего шаблона, сохраняя сырые выборы модели.
Неполный или неверный выбор даёт сохранённый отказ и диагноз, без скрытых
повторных вызовов. Другой LLM для сборки или аудита приложение не вызывает.

Настройки сравнения, фактические сообщения и model digests находятся в исходных
отчётах. Квантование Q4/Q5 проверено на одном справочном вопросе: качество
равноценное, Q4 потребовал меньше времени и аллокации. Temperature=0 выбрана
для предсказуемого ответа, её отдельный эффект не измерялся.

75 выходных токенов V7 — выборы модели, а не длина полной процедуры.
Сокращение времени относится ко всему изменённому контракту системы.
RSS и Ollama size_vram не равны полной физической памяти модели на Mac.
