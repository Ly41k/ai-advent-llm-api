# День 29 — итоговый комплект V7

Задание выполнено для выбранного кейса: локальная справка по репозиторию,
отказ при отсутствии доказательств и источниковая проверка периодической
работы worker Дня 18 на VPS. Новые запуски для завершения задания не нужны.

## Установка

Архив содержит папку `day-29-local-llm-optimization`.
Распакуй её **в корень ai-advent-llm-api**, объединив с существующей папкой дня.
Разреши замену совпадающих файлов. Не удаляй существующую папку целиком:
там находится твой кеш и дополнительные локальные результаты.
Этот архив содержит код, исходные отчёты, отдельные разборы и итоговые документы.
Python-код совпадает с уже установленным V7; новый индекс и модели не нужны.

## Что открыть

- `FINAL_REPORT.ru.md` — качество, скорость, квантование и ресурсы.
- `ASSIGNMENT_CHECKLIST.ru.md` — требования задания и доказательства.
- `SELECTED_PROFILE.json` — выбранная конфигурация и подтверждённая область.
- `review/control-v7-manual.json` — три контрольных процедурных ответа.
- `review/quality-transfer-v7-manual.json` — шесть ответов на новые формулировки.

## Проверка сохранённого результата без Ollama

Из корня репозитория:

```bash
python day-29-local-llm-optimization/experiments/quality_v7/main.py verify   day-29-local-llm-optimization/reports/check/quality-transfer-v7.json
```

Это чтение и проверка целостности, а не новые ответы. Для V7 используй именно
launcher V7: старые V1/V6 launcher не знают контракт выбора доказательств.
В сыром `generation.answer` хранятся выборы модели; `response.answer` —
сборка приложения. Автоматическая эвристика и отдельное содержательное ревью
сохраняются раздельно. Исходный optimization_verified не переписывался.

Если позднее повторишь опыт, кеш переиспользует три законченных ответа при
совпадении модели, сообщений, параметров, индекса и среды. Плохие законченные
ответы тоже сохраняются; повторение ради получения PASS не допускается.
