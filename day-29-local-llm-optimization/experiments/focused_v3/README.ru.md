# Focused V3: проверка короткого шаблона с примером

## Вывод по реальному V2

В `worker-focused-v2.json` получено три новых ответа `focused-q4`; три baseline
переиспользованы. Все новые ответы одинаковы. Нужный `worker.py` назван и
утверждение о ключах отсутствует, но инструкции по запуску и VPS остались.
Полный новый system prompt присутствует в отчёте: V2 действительно запускался.
Поэтому V2 не проходит ручную проверку краткости и релевантности, несмотря
на автоматический PASS. Фраза «for 24/7 operation» по-прежнему имеет слабую
привязку к e2-q5: этот фрагмент даёт инструкции, а пункт о 24/7 находится в e2-q6.
Исправленным этот ответ не считаем.

| Профиль | Медиана HTTP генерации, с | Токенов ответа в каждом повторе | Максимальная size_vram Ollama, GiB |
|---|---:|---:|---:|
| baseline | 26.28 | 278 | 11.09 |
| candidate-q4 | 16.08 | 180 | 9.56 |
| focused-q4 (V2) | 13.63 | 152 | 9.56 |

Это один вопрос, по три ответа. Первый запуск каждого prompt содержит долгий
prefill; в двух следующих почти весь prompt взят из KV-кэша. Значения size_vram
показывают сообщённую Ollama аллокацию модели, а не полную физическую память Mac.
V2 быстрее главным образом за счёт более короткого ответа; скорость декодирования
осталась около 11.3 токена/с. V2 не показал улучшения релевантности ответа.

## Что меняется в V3

Только task prompt: короткие инструкции на английском, явное правило «один
запрошенный компонент — один claim» и пример заполнения c1 при c2–c4=null.
Пример про запись показаний датчиков вымышленный и не содержит ответа на вопрос
Дня 18, worker.py или ожидаемого реального ID цитаты. Реальные IDs по-прежнему
ограничены схемой исходного пайплайна. Составные вопросы допускают несколько claims.

Это гипотеза для следующего эксперимента, не гарантия исправления. Модель,
параметры, retrieval, схема JSON, измерение ресурсов и seeds сохраняются.
Сравнение с V2 из прежнего отчёта покажет влияние изменения шаблона.

## Установка и запуск

Распакуйте папку `day-29-local-llm-optimization/` в корень существующего
репозитория. Архив добавляет только `experiments/focused_v3/`; исходные файлы,
кэш и предыдущие дополнения не заменяются. Новые профили запускайте именно
через приведённый ниже launcher.

```bash
python day-29-local-llm-optimization/experiments/focused_v3/main.py run \
  --profiles baseline focused-v3-q4 --case base-07 --repeats 3 \
  --retry-from day-29-local-llm-optimization/reports/check/worker-focused-v2.json \
  --output day-29-local-llm-optimization/reports/check/worker-focused-v3.json
```

При прежнем окружении baseline переиспользуется из кэша или указанного отчёта;
V1 и V2 повторно не запускаются. Три новых ответа выполняются только для V3.
После получения трёх ответов повтор этой команды не вызывает новых генераций.
Не меняйте исходные файлы V1, индекс, модели, series и настройки между запусками.
Путь `--retry-from` должен соответствовать фактическому расположению старого отчёта.
Проверка токенов и прогрев отдельно учитываются как maintenance calls.

```bash
python day-29-local-llm-optimization/experiments/focused_v3/main.py verify \
  day-29-local-llm-optimization/reports/check/worker-focused-v3.json
```

Критерий ручной проверки: каждый ответ прямо называет процесс и его нужную
функцию, не содержит инструкций по запуску или VPS, подтверждает каждый факт
указанной цитатой. Автоматический PASS не заменяет этой проверки.

## Offline проверка дополнения

Проверено на фиктивном локальном транспорте: три baseline сохранены без изменения,
для V3 выполнено ровно три новых ответа, повтор запуска не делает ни новых
answer calls, ни maintenance calls; prompt и код исходного измерителя сохраняют
ожидаемые независимые fingerprints. Реальная Qwen в этой среде не запускалась.
