# Итог Дня 29: конкретная справочная задача

## Выбранная конфигурация

Qwen2.5 14B Instruct Q4_K_M (qwen2.5:14b), Ollama на MacBook Pro M1 / 32 GiB.
Python 3.13.3, локальный bge-m3 и индекс Дня 21. Температура 0 в обеих сторонах
сравнения. Лимит ответа 2048 → 1024; окно контекста 16384 → 8192. Task prompt:
V3 с прямым ответом, одним claim для простой справки и null для ненужных слотов.
Реальные сообщения, параметры, model digests и контракты сохранены в каждом JSON.

Подтверждённая область — короткая справка по репозиторию и отказ при отсутствии
доказательств. Четыре вопроса × три ответа выбранного профиля: 12/12 ручных
проверок. Это проверенная небольшая выборка, не универсальная гарантия.

## Качество

В исходном ответе про worker модель называла правильный процесс, но добавляла
VPS-инструкции и приписывала чек-листу утверждение о GITHUB_TOKEN/Groq.
V3 дал один подтверждённый e2-q2 факт без посторонних инструкций. На Day 17
вместо повторения названия инструмента получен один факт с подходящей цитатой.
На Day 19 правильно перечислены все три инструмента одной подтверждённой фразой.
На вопрос о выручке модель отказалась от неподтверждённого ответа.

Полный контроль содержит пять вопросов × три ответа для каждого из двух
профилей. Оригинальный V5 имеет автоматические 15/15, но процедурный base-10
не прошёл ручное ревью. В его c3 точная команда связана с e1-q6, где её нет;
состояние службы также смешано с доказательством выполнения заданий.
Таким образом, у выбранного профиля 12/15 ручных PASS в полном наборе и
12/12 в его подтверждённой справочной области. Полный набор не объявлен
семантически верифицированным. Веса или ответы не исправлялись задним числом.

Ручные вердикты отделены от исходной эвристики и привязаны к job_key, trial и
SHA-256 сырого ответа в review/manual-review.json. Original optimization_verified
в сохранённых отчётах остаётся false. Ревью выполнено ассистентом по предоставленным JSON и цитатам.
Приложение не вызывало дополнительный модельный API для аудита.

## Скорость по вопросам

| Вопрос | Baseline, медиана HTTP с | Оптимизированный, медиана HTTP с | Токенов ответа | Ручной итог выбранного профиля |
|---|---:|---:|---:|---|
| base-06 | 56.28 | 45.62 | 154 → 61 | passed |
| base-07 | 26.28 | 6.09 | 278 → 67 | passed |
| base-08 | 57.24 | 45.33 | 187 → 60 | passed |
| base-10 | 64.11 | 13.20 | 290 → 144 | known limitation |
| negative-03 | 5.98 | 5.57 | 35 → 30 | passed |

Медианы рассчитаны по трём исходным наблюдениям каждого вопроса. Часть времён
переиспользована из предыдущих запусков и сохранена с исходными датами.
Прогрев и однотокенные проверки вместимости prompt учитываются отдельно.

Время зависит от prefill и KV-кэша. Для worker у выбранного профиля первый ответ
занял 49.56 с, следующие — 6.02 и 6.09 с. В более широком наборе смена вопросов
вызывает новые prefill: общая медиана не означает такое же ускорение каждого
нового вопроса. Например, GitHub-инструмент ускорился с 56.28 до 45.62 с медианы.
Скорость декодирования близка между baseline и Q4; основной выигрыш связан с
коротким ответом и настройками. Ускорение неполной процедуры не считается успехом.

## Память и ресурсы

Максимальная сообщённая Ollama аллокация в полном контрольном наборе:
baseline 11.19 GiB, выбранный профиль 9.67 GiB. Метрика — size_vram.
Она не равна полной физической памяти Mac. Apple использует общую память;
складывать process RSS и size_vram нельзя. Измеренные RSS, CPU, доступная
системная память и swap сохранены как исходные samples. Малый sampled RSS
не подтверждает, что модель занимает десятки мегабайт; эти наблюдения не дают
полной картины её физической памяти. GPU utilization не измерена.

## Квантование одной модели

На одинаковом вопросе worker использованы одинаковые фактические messages,
источники, temperature, max_tokens и num_ctx. Ollama metadata подтверждает
Q4_K_M и Q5_K_M одной Qwen2.5 14B Instruct с одним chat-template hash.
Ответы семантически равноценны; Q5 отличается оформлением имени файла.

| Метрика | Q4_K_M | Q5_K_M |
|---|---:|---:|
| Медиана HTTP генерации, с | 6.09 | 7.66 |
| Медиана decode tokens/s | 11.47 | 9.27 |
| Максимальная size_vram, GiB | 9.56 | 10.89 |

Q4 выбран для справочной задачи: на этом примере Q5 не улучшил качество и
потребовал больше времени и аллокации. Q4-времена взяты из предыдущего запуска,
Q5 измерен позднее. Три повтора одного вопроса не доказывают, что Q5 хуже на
других задачах. Размер скачанного файла модели не используется как замер памяти.

## Повторное использование

V5 выполнил только три новых ответа base-10 и переиспользовал 27 остальных.
Измеритель сохраняет готовые три ответа даже при плохом качестве. Полный
повтор при совпадении identity не создаёт новые answers, probes или warmups.
Импорт JSON позволяет сохранить результаты при пустом SQLite-кэше.
Изменение фактических сообщений создаёт новый ключ только для затронутого
вопроса. Вопросы, рубрики, модели, параметры, индекс и среда входят в identity.

Из исходного control-v5 можно получить сравнение четырёх справочных случаев
без новых генераций, при прежнем окружении:

```bash
python day-29-local-llm-optimization/experiments/focused_v3/main.py run \
  --profiles baseline focused-v3-q4 \
  --split all --case base-06 base-07 base-08 negative-03 --repeats 3 \
  --retry-from day-29-local-llm-optimization/reports/check/control-v5.json \
  --output day-29-local-llm-optimization/reports/check/factual-final.json
```

## Что не установлено

Нет измеренного отдельного эффекта temperature: обе стороны используют 0.
Параметры не объявляются глобально оптимальными. Нет fine-tuning, полного
исчерпывающего теста 20 вопросов или нового независимого набора после V5.
Процедурный вопрос оказался использован для дальнейшей настройки prompt,
поэтому его нельзя выдавать за untouched holdout. Оставшаяся процедурная
проблема сохранена как известное ограничение, а не скрыта автоматическим PASS.
