# AI Advent — День 1: Первый запрос к LLM через API

Первое практическое задание курса по работе с искусственным интеллектом через API.

Цель задания — создать консольного чат-бота, который отправляет запросы в языковую модель через Groq API, получает ответы и сохраняет историю текущего диалога.

## Что реализовано

* Подключение к Groq API.
* Безопасное получение API-ключа из файла `.env`.
* Отправка сообщений языковой модели.
* Использование ролей `system`, `user` и `assistant`.
* Настройка персонажа через системный промпт.
* Сохранение истории диалога во время работы программы.
* Консольный интерфейс.
* Обработка пустого пользовательского ввода.
* Обработка ошибок API.
* Завершение программы командой `выход`.

## Персонажи

Бот выступает в роли бортового помощника космического корабля по имени **Бублик**.

Пользователь — космический путешественник **Чебуратор**, который ищет приключения в галактике.

Бублик отвечает пользователю на русском языке.

## Системный промпт

Поведение чат-бота задаётся сообщением с ролью `system`:

```python
messages = [
    {
        "role": "system",
        "content": (
            "Ты бортовой помощник космического корабля по имени Бублик. "
            "Пользователя зовут Чебуратор. "
            "Он космический путешественник, который ищет "
            "приключения в галактике. "
            "Отвечай ему на русском языке."
        ),
    }
]
```

Системный промпт определяет:

* роль модели;
* имя помощника;
* информацию о пользователе;
* контекст общения;
* язык ответа.

## История диалога

Перед отправкой запроса сообщение пользователя добавляется в список `messages`:

```python
messages.append(
    {
        "role": "user",
        "content": user_input,
    }
)
```

После получения ответа сообщение модели также добавляется в историю:

```python
messages.append(
    {
        "role": "assistant",
        "content": bot_response,
    }
)
```

В результате список постепенно формирует полный диалог:

```text
system
user
assistant
user
assistant
user
assistant
```

При каждом новом запросе модели передаётся накопленная история. Благодаря этому Бублик может учитывать предыдущие сообщения пользователя.

История хранится только во время работы программы и удаляется после её завершения.

## Запрос к модели

```python
response = client.chat.completions.create(
    model="openai/gpt-oss-20b",
    messages=messages,
    temperature=0.8,
    reasoning_effort="medium",
)
```

Используемые параметры:

* `model` — языковая модель, которая обрабатывает запрос.
* `messages` — системный промпт и история текущего диалога.
* `temperature` — уровень вариативности ответов.
* `reasoning_effort` — объём вычислений, выделяемый модели на рассуждение.

## Обработка ошибок

Если переменная `GROQ_API_KEY` не найдена, программа завершается с понятным сообщением:

```text
Переменная GROQ_API_KEY не найдена.
Добавьте API-ключ в файл .env
```

Ошибки при обращении к API перехватываются:

```python
except Exception as error:
    messages.pop()
    print(f"Ошибка при обращении к LLM: {error}\n")
```

Если запрос завершился ошибкой, последнее сообщение пользователя удаляется из истории, поскольку ответ модели на него не был получен.

## Результат первого дня

В результате выполнения задания создан консольный чат-бот, который:

1. Получает сообщение пользователя.
2. Добавляет его в историю диалога.
3. Передаёт историю языковой модели через Groq API.
4. Получает и выводит ответ.
5. Добавляет ответ модели в историю.
6. Учитывает предыдущие сообщения при продолжении разговора.

Это базовая реализация диалога с LLM через API, которую можно расширять управлением форматом ответа, ограничением длины, сохранением истории в файл, потоковой генерацией и другими возможностями.
