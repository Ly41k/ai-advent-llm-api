# AI Advent — День 1: Первый запрос к LLM через API

Первое практическое задание курса по работе с искусственным интеллектом через API.

Цель задания — написать минимальное Python-приложение, которое отправляет запрос в языковую модель, получает ответ и выводит его в консоль.

## Что реализовано

* Подключение к Groq API.
* Получение API-ключа из переменной окружения.
* Отправка сообщений в языковую модель.
* Использование ролей `system` и `user`.
* Настройка поведения модели через системный промпт.
* Консольный интерфейс для ввода запросов.
* Обработка ошибок при обращении к API.
* Завершение программы командой `выход`.

## Используемые технологии

* Python
* Groq API
* GPT-OSS 20B
* python-dotenv
* Groq Python SDK

## Установка

Клонируйте репозиторий:

```bash
git clone <repository-url>
cd day-01-first-api-request
```

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его.

macOS/Linux:

```bash
source .venv/bin/activate
```

Windows:

```bash
.venv\Scripts\activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

## Настройка API-ключа

Создайте файл `.env` в корне проекта:

```env
GROQ_API_KEY=your_api_key_here
```

API-ключ можно получить в [Groq Console](https://console.groq.com/keys).

Файл `.env` содержит секретные данные и не должен добавляться в Git.

Пример `.gitignore`:

```gitignore
.env
.venv/
__pycache__/
*.pyc
```

## Как работает запрос

Каждый запрос содержит два сообщения:

```python
messages = [
    {
        "role": "system",
        "content": "Описание роли и поведения ассистента",
    },
    {
        "role": "user",
        "content": user_input,
    },
]
```

### Роль `system`

Определяет поведение, стиль общения и контекст ассистента.

В этом проекте модель выступает в роли бортового помощника космического корабля и отвечает пользователю на русском языке.

### Роль `user`

Содержит запрос, введённый пользователем в консоли.

## Параметры модели

```python
response = client.chat.completions.create(
    model="openai/gpt-oss-20b",
    messages=messages,
    temperature=0.8,
    reasoning_effort="medium",
    max_completion_tokens=1000,
)
```

* `model` — используемая языковая модель.
* `messages` — контекст и запрос пользователя.
* `temperature` — степень вариативности ответа.
* `reasoning_effort` — уровень рассуждения модели.
* `max_completion_tokens` — максимальное количество токенов в ответе.

## Обработка ошибок

Если переменная `GROQ_API_KEY` отсутствует, приложение завершится с понятным сообщением:

```text
Переменная GROQ_API_KEY не найдена.
Добавьте API-ключ в файл .env
```

Ошибки, возникшие при обращении к API, перехватываются и выводятся в консоль без аварийного завершения программы.

## Результат первого дня

В результате выполнения задания создано консольное приложение, которое:

1. Получает запрос пользователя.
2. Передаёт его языковой модели через Groq API.
3. Получает ответ модели.
4. Выводит результат в консоль.

Это базовый пример интеграции LLM через API, на основе которого можно добавлять историю диалога, управление форматом ответа, ограничения длины, потоковую генерацию и другие возможности.
