# Day 32 — backlog после курса

Course Minimum ограничен одним небольшим публичным PR. Ни один пункт ниже не нужен для offline-поставки и не разрешает дополнительные платные вызовы.

| Пункт | Почему отложен | Влияние | Риск текущего ограничения | Критерий закрытия |
|---|---|---|---|---|
| Fork PR | Требует отдельного анализа permissions/secrets | Нет ревью внешних forks | Необработанные внешние PR | Изолированный unprivileged intake и проверенная схема публикации без исполнения fork-кода |
| Inline comments | Обычного комментария достаточно для курса | Менее точная навигация в UI | Удобство, не качество анализа | Проверены LEFT/RIGHT, rename/delete, outdated revisions и повторная публикация |
| Multi-file архитектурный анализ | Не помещается в один малый контекст | Межфайловые дефекты могут пропускаться | False negatives | Отдельный фиксированный набор межфайловых примеров и согласованный бюджет |
| Kotlin/Detekt | Противоречит минимальному сценарию без запуска PR | Нет детерминированного Kotlin-анализа | AI может не заметить compiler/static defects | Изолированный runner, доверенная конфигурация, понятная модель угроз |
| Qwen/self-hosted runner | Сложнее и требует локального управления | Зависимость от Groq | Сетевые/квотные блокеры | Локальные замеры на M1 и безопасная изоляция runner от PR-кода |
| Автоисправления | Сейчас reviewer только advisory | Исправления делает человек | Больше ручной работы | Явное разрешение на каждое изменение, тесты и review отдельного patch |
| Многоступенчатое AI review | Умножает calls/стоимость | Нет второго semantic verifier | Некорректная интерпретация при правильных цитатах | Доказанное улучшение на фиксированном наборе и отдельный бюджет |
| RAG по коду и полный head-контекст | README+patch достаточно для демонстрации | Недостаток внешнего контекста | False positives/negatives | Безопасный immutable corpus, namespace tests и измеримое улучшение retrieval |
| Сравнение провайдеров/моделей | Не задача Course Minimum | Нет сравнительной оценки качества | Выбор модели не подтверждён benchmark | Независимые вопросы/PR, общие метрики, согласованные деньги |
| Большая regression suite | Ограничиваем время курса | Только базовые контракты и негативные проверки | Редкие крайние случаи | Набор реальных обезличенных дефектов с ожидаемыми verdicts |
| Полный human/semantic review workflow | Сейчас ручная проверка одного результата | Нет formal acceptance lifecycle | Ошибочный finding может выглядеть убедительно | Простой, проверенный audit trail без повторения Stage 7 |
| Production monitoring/CI hardening | Учебный workflow | Нет эксплуатации как сервиса | Поддержка/изменения runner/API | Угрозы, dependency/update policy, observability и failure drills |
| Точный локальный tokenizer | Для малого PR достаточно консервативного byte-BPE bound | Сильно урезанный контекст | Omitted hunks; служебный reserve ещё не проверен сервером | Фиксированный tokenizer/template, offline vectors и сверка с разрешённым server usage |
| Продвинутый secret scanner | Простые heuristics ограничены | Возможны false positives и пропуски необычных секретов | Утечка при неожиданном формате | Проверенный scanner без внешней отправки данных и набор synthetic cases |
| Автоматическая проверка branch/Environment policy | Проверяется владельцем перед live | Есть ручная конфигурационная проверка | Ошибочная настройка reviewer/branch restriction | Доступный read-only policy API и тестируемая проверка; не расширять permissions ради курса |
| Подпись provenance/отчётов | SHA256 достаточен для случайной порчи, не аутентификации | Нет cryptographic attestation | Недоверенные артефакты нельзя принимать извне | Подписанные artifacts с проверкой issuer/revision и явной границей доверия |
| Большие PR и 300+ комментариев | Жёсткие пределы защищают ресурсы | Такие PR пропускаются/публикация останавливается | Неполное покрытие | Bounded pagination/segmentation без скрытой мультигенерации |
| Перенос на другой репозиторий/владельца | Policy намеренно фиксирована | Нет универсальности | Ошибочная копия workflow может не работать | Явная конфигурация доверия и независимые namespace tests |

OpenAI резерв не означает задачу multi-provider. При реальном блокере Groq обсуждается минимальная ручная замена адаптера; автоматический fallback и параллельная отправка одному PR двум моделям не планируются.
