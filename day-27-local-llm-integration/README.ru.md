# Ревик — локальный агент проверки Kotlin перед коммитом

День 27 AI Advent. Отдельная CLI-утилита Python + Git pre-commit + Detekt + Ollama.

Ревик проверяет добавленные в Git index `.kt`/`.kts` файлы по конфигурации проекта `detekt/detekt.yml`, показывает нарушения с путями и строками, запрашивает объяснение у локальной Qwen и разрешает либо отклоняет коммит. Пути `common/`, `composeApp/`, `libs/` и другие модули обрабатываются одинаково. Проектные Gradle-файлы менять не требуется.

**Если `detekt/detekt.yml` отсутствует в Git index, проверка пропускается, коммит разрешается.** Проверяется staged-содержимое конфигурации и исходников, а не случайная версия в рабочем каталоге.

## Язык и стиль комментариев

В существующий `.revik.json` добавь два поля (сохрани свои `detekt_command`, baseline и остальные параметры):

```json
"language": "ru",
"tone": "light_troll"
```

| Настройка | Значения | По умолчанию |
|---|---|---|
| `language` | `ru`, `en` | `ru` |
| `tone` | `professional`, `light_troll`, `hard_troll` | `professional` |

- `professional`: деловое объяснение нарушения и конкретный способ исправления, без шуток.
- `light_troll`: максимум одна дружеская шутка про код/баг, затем полезное объяснение.
- `hard_troll`: более острый сарказм про реализацию, максимум две короткие шутки; исправления остаются основной частью ответа.

Примеры желаемого стиля, **не результаты реального запуска модели**:

| Стиль | Русский | English |
|---|---|---|
| professional | Магическое число затрудняет понимание кода. Вынеси значение в именованную константу. | A magic number obscures intent. Extract it into a named constant. |
| light_troll | Походу, этот баг у нас уже член команды. Вынеси число в константу, чтобы его назначение стало понятным. | Looks like this bug has joined the team. Extract the number into a named constant. |
| hard_troll | Это магическое число уже повысили, а имя ему так и не дали. Пора оформить его как именованную константу. | This magic number got promoted before it even got a name. Give it a named constant. |

Модель получает инструкции выбранного языка и стиля. Конкретная формулировка и соблюдение стиля зависят от локальной модели; программной гарантии языка свободного текста нет. Шутки направлены на код и баги, а не на личность разработчика. Упоминание «члена команды» — метафора, а не утверждение, что баг встречался раньше. Ревик не хранит историю повторений багов.

Язык интерфейса, сообщений о skip/allow/block и заголовков отчётов переключается приложением. Оригинальные сообщения Detekt, имена правил, JSON-ключи и низкоуровневые технические диагностики сохраняются без перевода. Стиль действует только на объяснение LLM; решение Detekt, пути и строки не меняются.

Можно временно переопределить настройки без изменения файла:

```bash
python3 tools/revik-agent/revik_cli.py check --language en --tone professional
python3 tools/revik-agent/revik_cli.py doctor --language ru --tone hard_troll
```

CLI-флаги действуют на один вызов. Автоматический hook каждый раз читает `.revik.json`. Для постоянного изменения языка/стиля редактируй этот файл; переустанавливать hook не нужно.

При обновлении существующей установки замени каталог `tools/revik-agent/revik/` из нового архива целиком: добавился `i18n.py`, изменился `app.py`. `revik_cli.py` и установленный hook остаются совместимыми. Локальный `.revik.json` не перезаписывай шаблоном. Каталог `examples` для обычной работы hook по-прежнему не нужен, но нужен для `live_demo.py`.

Живую демонстрацию можно запустить с выбранным стилем:

```bash
python3 live_demo.py --detekt-jar /absolute/path/to/detekt-cli.jar \
  --language ru --tone light_troll --model qwen2.5:14b
```

## Быстрое подключение к твоему KMP-проекту

Требования: macOS/Linux, Git, Python 3.10+ (3.13 подходит), JDK для выбранной версии Detekt, установленный Detekt CLI, Ollama и скачанная локальная модель. Никаких Python-зависимостей устанавливать не нужно. В архиве исходники агента и документация; JDK, модель и Detekt распространяются отдельно.

1. Распакуй архив и скопируй папку `revik-agent` в корень своего проекта:

```text
EventConnectMobile/
  detekt/detekt.yml
  common/
  composeApp/
  tools/revik-agent/
```

2. Установи Detekt CLI. Для воспроизводимого подключения можно использовать отдельный JAR **той же версии, что Detekt в твоём Gradle-проекте**. Проверенная здесь версия — 1.23.8; пример ниже рассчитан на неё. Если у проекта другая версия, возьми её CLI и совместимые плагины.

```bash
# Из корня KMP-проекта. JDK уже может быть установлен с Android Studio.
java -version
python3 --version

mkdir -p tools/revik-agent/.vendor
curl --fail --location \
  https://github.com/detekt/detekt/releases/download/v1.23.8/detekt-cli-1.23.8-all.jar \
  --output tools/revik-agent/.vendor/detekt-cli.jar
java -jar tools/revik-agent/.vendor/detekt-cli.jar --version
```

Другой вариант: `brew install detekt`, если установленная версия совместима с конфигурацией проекта. Тогда используй `"detekt_command": ["detekt"]`. Для IDE лучше абсолютный путь к исполняемому файлу: `command -v detekt`. Аналогично можно заменить `java` абсолютным путём к JDK.

3. Создай `.revik.json` **в корне KMP-проекта**:

```json
{
  "language": "ru",
  "tone": "professional",
  "detekt_config": "detekt/detekt.yml",
  "detekt_command": ["java", "-jar", "tools/revik-agent/.vendor/detekt-cli.jar"],
  "detekt_plugins": [],
  "baseline": null,
  "build_upon_default_config": false,
  "model": "qwen2.5:14b",
  "ollama_url": "http://127.0.0.1:11434",
  "require_llm": true
}
```

`build_upon_default_config` установи таким же, как `buildUponDefaultConfig` в Gradle. `false` означает правила из твоей конфигурации без объединения с полным стандартным набором. Часть правил Detekt имеет собственные значения по умолчанию.

4. Запусти Ollama и скачай модель, если её ещё нет:

```bash
open -a Ollama
# Уже установленную qwen2.5:14b повторно скачивать не нужно.
ollama pull qwen2.5:14b
ollama list
```

Если используешь `qwen2.5:7b`, замени `model` в `.revik.json`. Агент обращается только к loopback HTTP, отключает HTTP-прокси и redirects, отклоняет cloud-теги и модели с remote backend. Облачного fallback и API-ключей нет. Для проверки автономности заранее скачай зависимости и модель, затем отключи интернет.

5. Проверь соединение и установи hook:

```bash
python3 tools/revik-agent/revik_cli.py doctor
python3 tools/revik-agent/revik_cli.py install
```

`doctor` выполняет Detekt `--version` и **реальный** запрос в локальную модель. Это диагностика, а не проверка твоих staged-файлов. `install` сохраняет абсолютный путь к этому интерпретатору Python и утилите: после переноса проекта или удаления venv повтори установку.

6. Добавь исходники и конфигурацию, проверь их и сделай коммит:

```bash
# Укажи собственные изменённые файлы; git add -p поддерживается.
git add detekt/detekt.yml .revik.json tools/revik-agent
# Затем добавь нужные изменения Kotlin в index.
python3 tools/revik-agent/revik_cli.py check

git commit -m "Add Revik local pre-commit agent"
```

Ручной `check` и автоматический hook используют одну логику. Возврат 0 разрешает коммит, 1 означает найденные нарушения, 2 — техническую ошибку, 130 — прерывание. Обычные коммиты из терминала и IDE используют hook, если IDE вызывает Git с проверками.

## Что именно происходит при коммите

1. `git write-tree` фиксирует дерево Git index, включая временный index Git при специальных режимах коммита.
2. Ревик сравнивает это дерево с HEAD и выбирает добавленные/изменённые `.kt` и `.kts`. Переименованный Kotlin-файл проверяется под новым именем; удалённый не проверяется. На первом коммите проверяются все staged Kotlin-файлы.
3. Если изменена конфигурация или явно настроенный baseline, проверяется всё staged Kotlin-дерево. Без Kotlin-файлов проверка пропускается.
4. Исходники и конфигурация копируются во временную папку напрямую из Git blobs. Рабочие файлы, index и stash не изменяются.
5. Detekt CLI выполняет анализ с `--config` и создаёт новый XML. Старые отчёты не используются. Любое найденное нарушение блокирует коммит, даже если порог Detekt позволяет вернуть 0. Техническая ошибка или отсутствие отчёта также блокируют его.
6. Ревик отправляет результаты и короткие фрагменты staged-кода в локальную LLM. На чистом анализе модель получает сводку без исходников и подтверждает результат этого запуска.
7. Приложение выводит ответ, точные пути и строки, сохраняет JSON/Markdown/HTML. Решение не меняется на основании свободного текста LLM.
8. Перед завершением повторно проверяется tree ID index. Если index изменился во время анализа, коммит останавливается для повторной проверки.

LLM — помощник для объяснения и предложений исправления. Правила Detekt выполняет настоящий Detekt. Модель не определяет номера строк, не создаёт официальные ссылки, не исправляет и не добавляет файлы автоматически. Это ограничивает влияние случайных модельных ошибок на решение.

По умолчанию `require_llm=true`: если Ollama выключен, модель не скачана, вернулся пустой ответ или генерация оборвалась по лимиту, коммит блокируется с технической ошибкой. При большом объяснении можно увеличить `num_predict`/`llm_timeout` или уменьшить число нарушений в запросе. Чтобы разрешать чистый Detekt при недоступной модели, явно установи `require_llm=false`. При этом нарушения Detekt всё равно блокируют коммит; успешная сдача Дня 27 требует отдельно показать настоящий ответ локальной LLM.

## Ссылки и отчёты

В консоли каждое нарушение печатается так:

```text
/absolute/project/common/src/commonMain/kotlin/SomeFile.kt:18:9: detekt.MagicNumber: ...
```

Такие строки удобны для перехода из терминала/IDE. Дополнительно выводится `file:///.../latest.html`, а внутри отчёта есть ссылки `vscode://file/...:line:column` и ссылки на сами файлы в Markdown/JSON. CLI-строки подходят для Android Studio; поддержка клика зависит от терминала. Ссылки VS Code требуют установленного обработчика этого протокола.

Отчёты лежат в Git-служебном каталоге `revik-reports`:

```bash
# Из корня проекта; корректно также для worktree и core.hooksPath.
git rev-parse --git-path revik-reports
# В обычном репозитории:
open .git/revik-reports/latest.html
```

Файлы: `latest.json`, `latest.md`, `latest.html`. Новый запуск заменяет предыдущие отчёты, в том числе при skip/error, чтобы старый PASS не выглядел актуальным. Они не попадают в коммит. Для сдачи скопируй JSON успешной live-проверки отдельно.

**Строки относятся к staged-версии. Ссылки открывают рабочий файл.** Если в нём есть незакоммиченные правки, номера строк могут отличаться. В JSON есть tree ID проверенной версии.

В LLM отправляется не более 12 нарушений по умолчанию, по 3 строки контекста с каждой стороны (до 300 символов на строку). Все нарушения остаются в отчёте. Количество пропущенных из LLM-запроса нарушений указано в payload. Объяснение LLM остаётся рекомендацией и требует ревью.

## Твой каталог `detekt/baselines`

Ревик автоматически использует `detekt/detekt.yml`, но **не угадывает baseline** из каталога `detekt/baselines/`: разные KMP-модули и платформы могут иметь разные baseline.

Если в проекте один общий baseline, добавь его точный путь:

```json
"baseline": "detekt/baselines/baseline.xml"
```

Он должен быть добавлен в Git index. Его правила подавления применяет Detekt. При `baseline=null` baseline не используется: старые нарушения в изменённых файлах тоже могут блокировать коммит. Если нужна идентичность конкретным Gradle-задачам с несколькими baseline, classpath или вариантами Android, эту интеграцию нужно расширить под build-конфигурацию проекта. Скриншот не содержит этих настроек.

Если `detekt.yml` ссылается на внешние ресурсы (например шаблон лицензии), текущая версия не переносит их автоматически в snapshot; потребуется добавить их перенос в `materialize` либо убрать зависимость из hook-профиля. Ошибка анализа будет видимой и блокирующей.

## Плагины и границы KMP-проверки

Если Gradle Detekt использует `detekt-formatting`, Compose rules или собственные rules JAR, укажи **те же совместимые JAR** в `detekt_plugins`, например:

```json
"detekt_plugins": ["tools/revik-agent/.vendor/detekt-formatting.jar"]
```

Их надо установить до офлайн-запуска. Плагин исполняется локально внутри Detekt. Автокоррекция не включена.

Эта версия выполняет **анализ Kotlin AST через CLI без type resolution**. Она подходит для style/naming/complexity и других правил, не требующих resolved types. Она не заменяет компиляцию KMP, Android Lint или платформенные Gradle Detekt-задачи с classpath. Правила с type resolution могут не выполниться; присутствие YAML не означает, что все такие правила проверены. Для полной проверки оставь существующий Gradle/CI pipeline. Также сборочные ошибки Kotlin не гарантированно выявляются этим hook.

Для первой установки рекомендуется совпадение версии Detekt с Gradle. Код проверен с CLI 1.23.8; совместимость с Detekt 2.x не заявлена. Правила применяются ко всему содержимому изменённого файла, а не только к изменённым строкам. Внешние submodule не обходятся. Symlink-исходники/конфигурации отклоняются.

## Существующий pre-commit hook

Установщик использует `git rev-parse --git-path hooks/pre-commit`, учитывает Git worktree и `core.hooksPath`. Существующий чужой hook не перезаписывается. Чтобы объединить проверки, вручную добавь в существующий hook до успешного завершения:

```sh
# Python и путь к CLI должны соответствовать твоему проекту.
python3 tools/revik-agent/revik_cli.py check || exit $?
```

Hook manager (например pre-commit) может запускать эту же команду. Отдельный вызов должен происходить один раз на коммит, а не на каждый файл.

Для удаления удали установленный файл `pre-commit` только если он содержит строку `# Installed by Revik 1.0`. Из чужого hook удали только добавленную команду. Git hook локальный: каждый разработчик устанавливает его отдельно. Его можно обойти `git commit --no-verify`; обязательный командный контроль обеспечивается CI, а не одним hook.

## Проверки без реальной модели

```bash
python3 -m unittest discover -s tools/revik-agent/tests -v
```

Тесты используют временные Git-репозитории, настоящий запуск hook и commit, scripted Detekt CLI и локальный HTTP-сервер с Ollama-контрактом. Они не запускают настоящую Qwen и не доказывают качество её рекомендаций. Проверены partial staging, ошибки/пустой/обрезанный ответ модели, remote backend, запрет внешнего URL, отсутствие конфигурации, baseline, сохранение чужого hook и изменение index во время анализа.

## Живая проверка и сдача Дня 27

Из папки с распакованным архивом можно проверить агент без подключения к рабочему KMP-проекту:

```bash
python3 live_demo.py \
  --detekt-jar /absolute/path/to/detekt-cli.jar \
  --model qwen2.5:14b \
  --output revik-live.json
```

Или `python3 live_demo.py --detekt-bin /absolute/path/to/detekt --model qwen2.5:14b`.

Скрипт создаёт временный Git-репозиторий с небольшой конфигурацией MagicNumber, устанавливает настоящий hook и пробует два реальных коммита:

- Kotlin с локальным `val factor = 42` → Detekt находит нарушение → модель объясняет → коммит блокируется;
- вариант с `private const val FACTOR = 42` → Detekt проходит → модель подтверждает → коммит создаётся.

Твой рабочий проект не изменяется. Скрипт сохраняет отчёт после обоих случаев. `all_passed=true` означает правильные решения, полученные ответы локальной модели и ожидаемые exit codes Git. Если модель недоступна, сценарий считается неуспешным.

Для видео покажи установленную Qwen, live-demo, вывод LLM, отказ плохому коммиту, успешный исправленный коммит и JSON. После скачивания модели/Detekt можно повторить демонстрацию без интернета.

| Требование Дня 27 | Реализация |
|---|---|
| Реальное приложение | CLI-утилита + Git pre-commit hook |
| Запросы к локальной LLM | Ollama `/api/chat`, скачанная Qwen |
| Получение и отображение ответов | Терминал + JSON/Markdown/HTML |
| Работа без облачной модели | Только loopback Ollama; облачного провайдера нет |

В этом окружении проверены offline-тесты и настоящий Detekt CLI. Настоящая Qwen на твоём Mac здесь недоступна: живой результат нужно получить командой выше. Смотри `VALIDATION.md` для точного разделения проверок.

## Файлы и настройки

- `revik_cli.py`, `revik/__main__.py` — точки входа;
- `revik/app.py` — index snapshot, Detekt, Ollama, reports, install;
- `revik.example.json` — пример настроек;
- `live_demo.py` — демонстрация реальных коммитов с настоящей моделью;
- `examples/` — минимальная конфигурация и good/bad Kotlin;
- `tests/test_revik.py` — интеграционные проверки;
- `VALIDATION.md` — фактические проверки поставки.

Дополнительные настройки `.revik.json`: `detekt_timeout=180`, `llm_timeout=180`, `num_ctx=8192`, `num_predict=1500`, `max_findings_for_llm=12`, `snippet_lines=3`. Опечатки в ключах отклоняются. `.revik.json` — локальная конфигурация запуска из рабочего каталога; она не является детект-правилами и не берётся из snapshot. Пользователь контролирует свою hook-конфигурацию. Detekt YAML и baseline берутся из index.

Никакие секреты или весь репозиторий в запрос не добавляются. Фрагменты кода остаются в обычном локальном Ollama и в локальном отчёте; сторонний сервер, притворяющийся Ollama на loopback, этим механизмом не аттестуется.
