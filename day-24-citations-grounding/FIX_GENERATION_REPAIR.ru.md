# Патч v5 после регрессии recheck_v4.json

Живой v4 прошёл только 1/4 вопросов: корректны четыре состояния FSM. Для 01 и 09 draft не прошёл локальную проверку идентификаторов; для 10 сначала получен китайский текст, затем неполная отсылка к другому документу. Scope_auditor вызван только для 02. Защита отказала в публикации этих трёх ответов, но положительные вопросы не пройдены. Разбор: reports/live/REVIEW_recheck_v4.ru.md.

## Изменения

- Восстановлен порядок JSON-полей text → citations, использованный в v3, и ориентир на один-два прямых claim. Генератору повторно предъявляется исходный вопрос после контекста: перечень таблиц, заголовок или ссылка на инструкцию не заменяют запрошенный механизм/проверки. Quote-first — возможный вклад в регрессию; изолированного live-эксперимента с одной изменённой переменной пока нет.
- Русский язык задан явно перед контекстом, после него и в repair. Проверка наличия русской поясняющей речи сохраняется и блокирует также китайский/другой нерусский draft. Цитаты не переводятся.
- Repair получает не только IDs, но и короткие дословные фрагменты из уже найденного каталога с идентификаторами draft. Максимум два фрагмента на имя, 12 имён и 4000 символов текста. Эталонные ответы не передаются модели. Приложение не добавляет такие цитаты автоматически: новый draft проходит все прежние проверки.
- Bare-идентификатор `analysis` считается буквально присутствующим в `analysis.verify_report`, как компонент qualified route. Это подтверждение написания имени, а не доказательство типа сервера, транспорта или поведения. Полные составные названия и названия сервисов по-прежнему не проходят по похожему префиксу; смысловые этапы обязательны.
- В evaluation `well_formed_refusal` означает корректную форму unknown, а `correct_refusal` применяется только к отрицательному контролю. Unknown на положительном вопросе не засчитывается как успех. При reason=evidence_validation_failed текст отказа теперь сообщает, что не удалось подтвердить ответ по источникам, не утверждая, что нужных данных вообще нет в контексте.

Порог, candidate/final K, индекс, выбор моделей, точность цитат, основной verifier, scope_auditor и лимит двух draft-попыток сохранены. Протокол: `quote-ids-scope-v5`.

## Применить и проверить

Скопируйте папку `day-24-citations-grounding` из кумулятивного архива в корень проекта с заменой совпадающих файлов. Сохраните свои локальные reports/check (Finder: Merge с заменой совпадений). Пересборка индекса для этого патча не нужна.

В корне репозитория, в вашей .venv и при работающем Ollama:

```bash
python day-24-citations-grounding/test_day24.py -v
python day-24-citations-grounding/main.py evaluate \
  --questions day-24-citations-grounding/questions_recheck.json \
  --output day-24-citations-grounding/reports/check/recheck_v5.json
```

Ожидается 52 теста и OK. После живого прогона пришлите recheck_v5.json, включая случаи с кодом выхода 1. Для answered нужны четыре validation-флага true: quotes_exact, sources_valid, semantic_supported, scope_supported. Затем вручную проверьте соответствие каждого claim собственным цитатам и полноту ответа.

| Вопрос | Критерий |
|---|---|
| 01 | Правило изоляции истории выбранного диалога по идентификатору и загрузка из SQLite после перезапуска. Перечня таблиц недостаточно; свойства task FSM не переносить на диалоги. |
| 02 | planning, execution, validation, done; fail не объявлять состоянием из-за метки стрелки. |
| 09 | Цепочка GitHub → analysis → storage → read → verify и сравнение прочитанного отчёта с исходной сводкой. Не приписывать проверку storage только потому, что он читает файл. |
| 10 | На русском: конкретные status/journalctl-команды и наблюдение свежей сводки/повторного сбора. Не приписывать запуск main.py unit-сервису worker. |

После подтверждения четырёх ответов нужен полный прогон 10 + 2:

```bash
python day-24-citations-grounding/main.py evaluate \
  --output day-24-citations-grounding/reports/check/evaluate_v5.json
```

## Проверка подготовки

52 теста Дня 24, 34 регрессионных теста Дней 21–23 и controlled replay 10 + 2 прошли. Четыре новых теста проверяют namespace в qualified route без доказательства транспорта, реальные ограниченные repair-подсказки, отсутствие авто-подстановки доказательств и непринятие положительного unknown как отрицательного успеха.

**Live-качество v5 на Qwen здесь не измерено.** Fixtures подтверждают работу gates и протокола, а не способность модели выбрать правильные факты. Результаты предыдущих запусков сохранены без изменения модельных ответов и summary. Задание остаётся открытым до полного live-прогона и ручной проверки.
