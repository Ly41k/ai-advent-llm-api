## Применение

Скопируйте содержимое папки day-24-citations-grounding из архива в одноимённую папку проекта с заменой совпадающих файлов. Не удаляйте локальную reports/check. Индекс пересобирать не нужно. Из корня проекта, с активной .venv:

```bash
python day-24-citations-grounding/test_day24.py -v
python day-24-citations-grounding/main.py \
  --answer-model qwen2.5:14b \
  --verifier-model qwen2.5:14b \
  evaluate \
  --output day-24-citations-grounding/reports/check/evaluate_v7_both14b.json
```

Ожидается58 тестов и OK. Evaluate проверяет все10 положительных +2 отрицательных. Пришлите evaluate_v7_both14b.json даже при exit code1. Technical error даёт2.

Для answered обязательны источники source/section/chunk_id, дословные quotes и четыре validation-флага true. Затем ручная сверка: поддерживает ли каждая собственная цитата всё утверждение и отвечает ли текст на вопрос. Ожидаемый смысл 01: сообщения только выбранного conversation_id идут в запрос; выбранная история загружается из SQLite. Ожидаемый смысл 10: проверить сервис/журнал и наблюдать результаты периодического worker, например повторные сводки/сохранённые снимки, как описано источниками. Это пояснения для ручной проверки; они не зашиты в production код или вопросы для LLM.

Unknown на положительном вопросе — непройденный контроль. На отрицательном нужны «не знаю», clarification, пустые sources/quotes. Высокий cosine сам по себе не означает наличие ответа. Fixtures не заменяют реальную модель и ручную оценку.
