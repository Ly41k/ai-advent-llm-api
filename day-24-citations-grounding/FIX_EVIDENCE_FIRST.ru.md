# v8 — доказательства до ответа и разделение аудита

Основание: полный evaluate_v7_both14b.json, автоматически6/10 и вручную5/10. Детали и примеры ожидаемых ответов — reports/live/REVIEW_evaluate_v7_both14b.ru.md.

- №1/5/9: нужные части источников найдены, но не процитированы; один repair часто копирует прежний draft. Новый selector выбирает доказательства до текста ответа, а repair начинает с нового выбора. Генератор не получает прежний draft и весь каталог.
- №7: primary отвергает периодичность вопреки цитате «через заданный интервал». В v8 истинность проверяется отдельным нейтральным per-claim auditor, без исходного вопроса и оценки полноты; разрешены перевод и обычные логические следствия кода/текста. Успех реального14B на этом случае пока не измерен.
- №10: primary считает список команд полным ответом. Новый coverage auditor видит только текст ответа; должен предъявить собственный excerpt для наблюдаемого результата отдельно от действия. Один и тот же excerpt отклоняется локально. Скриптовый тест старого command-only draft с incomplete verdict блокирует публикацию; это не измерение способности LLM найти неполноту.

Другие изменения: compact-каталог исключает полностью вложенные короткие fragments; IDs и дословные тексты не меняются. Detailed metadata остаётся в trace. CLI выбирает14B; доступны context/generation/timeout options. Сохраняются Ollama prompt_eval_count/eval_count/done_reason/длительности, если сервер вернул их. done_reason=length не может стать опубликованным ответом.

Реальных input-token counts у старого v7 нет, поэтому контекстная обрезка не объявляется причиной его ошибок. Не снижаем порог по четырём положительным отказам: нужные сведения уже есть в отобранных чанках. Профиль fixed20/5/.50/heuristic продолжен для сравнимого живого запуска.
