# Патч v4: отдельная проверка области действия утверждений

Это обновление кода после `recheck_v3.json`. Источники и все 12 цитат четырёх ответов были корректны, но вручную подтверждены только 02 и 09. В ответе 01 FSM задачи ошибочно перенесён на изоляцию диалогов; в 10 systemd-сервису приписан запуск и worker, и агента. Общий verifier пропустил обе ошибки.

## Что изменено

- После основного verifier добавлен отдельный структурированный вызов `scope_auditor`. Он сравнивает субъект, действие и объект каждого claim с его собственными цитатами. Основной положительный verdict ему не передаётся. Он не получает нецитируемые факты из полных чанков.
- Auditor должен назвать неподтверждённые части буквально в `unsupported_spans`. Каждый фрагмент проверяется как подстрока именно своего claim. Проверяются все ID ровно один раз, типы, поля и согласованность supported со списком неподтверждённых частей. Отрицательный или невалидный результат не может быть заменён положительным verdict основного verifier.
- Генератор выбирает citations перед text в схеме и получает правило по умолчанию дать одно прямое утверждение. Он должен объяснять механизм разделения контекста, а не только его сохранение, и не объединять отдельные способы запуска процессов.
- Для русского вопроса локально отклоняется claim целиком на английском. Это узкая проверка наличия русской поясняющей речи вне inline-кода, а не полноценное определение языка. Цитаты и идентификаторы остаются дословными.
- Одна повторная генерация сохраняется. При повторном отказе проверок возвращаются unknown и просьба уточнить. Без контекста выше порога генератор, verifier и auditor не вызываются.

Успешный ответ теперь требует `quotes_exact`, `sources_valid`, `semantic_supported` и `scope_supported` равными true. JSON сохраняет основной verdict, `scope_verdict` и исходные ответы моделей в `model_calls`. Протокол — `quote-ids-scope-v4`.

Обычно получается три structured-вызова: draft → verifier → scope_auditor. При repair максимум шесть. Вызовы embedding и опционального LLM rewrite учитываются отдельно. Это дополнительная задача для выбранного `--verifier-model`, по умолчанию того же Qwen; она не является независимой моделью и тоже может ошибаться.

## Что делать с архивом

1. Распакуйте `day24-scope-audit-fix-v4.zip` в отдельную временную папку.
2. Скопируйте из неё папку `day-24-citations-grounding` в корень вашего репозитория с заменой существующих файлов этой папки. При выборе Finder между Merge и Replace используйте Merge с заменой совпадающих файлов, чтобы сохранить ваши локальные `reports/check`.
3. Откройте терминал в корне репозитория и используйте свою активную `.venv`.

Этот патч содержит только папку Дня 24 и инструкцию/манифест. Готовый индекс `knowledge.db` подходит: корпус и код Дней 21–23 патчем не изменяются. Пересборка понадобится при отдельном изменении корпуса или embedding-модели.

## Команды

```bash
python day-24-citations-grounding/test_day24.py -v
python day-24-citations-grounding/main.py evaluate \
  --questions day-24-citations-grounding/questions_recheck.json \
  --output day-24-citations-grounding/reports/check/recheck_v4.json
```

Ожидается 48 автономных тестов и OK. `questions_recheck.json` содержит четыре исходных вопроса 01, 02, 09, 10. После запуска пришлите `reports/check/recheck_v4.json`. Не меняйте порог ради прохождения уже просмотренных вопросов.

| Вопрос | Проверить по смыслу |
|---|---|
| 01 | Разделение сообщений выбранного диалога по отдельному идентификатору и загрузка его истории из SQLite после перезапуска. Свойства FSM задачи не переносятся на диалоги. |
| 02 | planning, execution, validation, done. fail не становится отдельным состоянием только из-за подписи стрелки. |
| 09 | Маршрут GitHub → analysis → storage → read → verify; сравнение прочитанного отчёта с исходной сводкой. |
| 10 | Конкретные status/journalctl-команды, наблюдение свежей сводки/повторного сбора; не приписывать сервису запуск агента. Ответить на русском. |

Положительный automated verdict требуется, но не заменяет ручную проверку. Unknown на положительный вопрос защищает от неподтверждённого ответа, но означает, что этот контрольный вопрос ещё не пройден.

После подтверждения этих четырёх ответов выполните полный набор 10 положительных + 2 отрицательных:

```bash
python day-24-citations-grounding/main.py evaluate \
  --output day-24-citations-grounding/reports/check/evaluate_v4.json
```

Код 1 означает непройденные проверки; JSON и Markdown при этом сохранены и нужны для разбора. Код 2 — техническая ошибка.

## Что уже проверено

48 тестов Дня 24 и 34 теста Дней 21–23 прошли на Python 3.12.14. Восемь новых тестов проверяют блокировку ошибочной атрибуции при положительном основном verdict, ограниченный repair, строгий формат auditor, отсутствие обхода при пустом/невалидном результате, передачу только собственных цитат, технические ошибки и исправление языка ответа. HTTP/SQLite/CLI-интеграция проверяет и новый этап.

Контролируемый replay 10 примеров и 2 отказов прошёл, но все ответы и вердикты в нём заданы как fixtures. **Живой Qwen на v4 здесь не запускался.** То, что программа правильно исполняет отрицательный verdict, не доказывает, что реальная модель найдёт каждую ошибку. Задание окончательно закрывается после живого полного прогона и сверки смысла.
