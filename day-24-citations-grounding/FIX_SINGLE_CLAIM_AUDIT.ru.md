# Патч v6: проверка отдельного утверждения

В recheck_v5.json снова подтверждён только 1/4 ответов. На вопросе 09 scope_auditor отвергает факты, буквально присутствующие в цитатах; на 10 основной verifier пропускает неверное назначение команд, а scope блокирует публикацию. Подробнее: reports/live/REVIEW_recheck_v5.ru.md.

Что изменилось:

- Один нейтральный audit на claim; statement и собственные evidence[].text передаются явно. Нет предыдущего verdict, чужих claim, исходного вопроса или нецитируемого текста.
- Минимальный ответ аудитора reason/supported; привязка claim_id выполняется приложением. Отрицательный/невалидный ответ по-прежнему блокирует публикацию. unsupported_spans в итоговой диагностике содержит всё отвергнутое утверждение, а не точную локализацию ошибки.
- heading/kind извлекаются из Markdown для выбора цитат. Их нельзя использовать как доказательство поведения.
- Многословный ASCII inline code должен буквально присутствовать в собственных цитатах. Наличие команды не доказывает её назначение: оба смысловых gate остаются обязательными.

Протокол quote-ids-scope-single-v6. Порог 0.50, candidate-K=20, final-K=5, модели и индекс прежние. Одна повторная генерация; на попытку 2 + число claim вызовов, максимум 10 за две попытки. Эти изменения ещё не измерены на живом Qwen.

## Применение

Скопируйте папку day-24-citations-grounding из архива в корень своего проекта с заменой совпадающих файлов. Сохраните локальные reports/check. Индекс пересобирать не нужно. Команды из корня репозитория, с активной .venv:

```bash
python day-24-citations-grounding/test_day24.py -v
python day-24-citations-grounding/main.py evaluate \
  --questions day-24-citations-grounding/questions_recheck.json \
  --output day-24-citations-grounding/reports/check/recheck_v6.json
```

Ожидается 56 тестов и OK. Пришлите recheck_v6.json даже при exit code=1: отчёт сохраняется. Ошибка подключения или модели даёт exit code=2 и требует отдельного разбора.

Для answered обязательны непустые sources/quotes и четыре validation-флага true. Вручную проверяем:

| Вопрос | Ожидаемый смысл — не строковый шаблон |
|---|---|
| 01 | UUID/выбранный conversation_id разделяет сообщения; после выбора диалога история загружается из SQLite. |
| 02 | planning, execution, validation, done; fail обозначает переход, а не отдельное состояние. |
| 09 | GitHub → analysis summary → storage save/read → analysis verify; считанный отчёт сравнивается с исходной сводкой. |
| 10 | Проверка состояния/logs worker и результата запланированного сбора; status не запускает агент и не запрашивает сводку. Worker и агент не следует объединять в один запуск сервиса без доказательств. Пример 60 минут не обязательный интервал. |

После подтверждения четырёх вопросов выполните полный набор:

```bash
python day-24-citations-grounding/main.py evaluate \
  --output day-24-citations-grounding/reports/check/evaluate_v6.json
```

Проверить все 10 положительных ответов по собственным цитатам, источникам и полноте. Два отрицательных должны дать «не знаю», clarification и пустые sources/quotes. Сильный cosine не гарантирует наличие ответа. Скриптовый PASS verifier не заменяет ручную оценку.

## Проверки в среде подготовки

56 тестов Дня 24 + 34 теста Дней 21–23 = 90 PASS. Controlled replay 10 + 2 использует заранее заданные ответы и решения: это проверка контракта, не живое измерение bge-m3/Qwen. Архив проверен после распаковки поверх базового репозитория. Нет Ollama или этих моделей в среде подготовки. Задание остаётся открытым до успешного полного live-прогона и ручной проверки.
