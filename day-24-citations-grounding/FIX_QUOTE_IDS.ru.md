# Исправление выбора цитат — 2026-10-03

Это описание первого патча. В текущей версии 31 тест; следующий результат worker_fixed.json и исправление смысла ответа разобраны в FIX_ANSWER_VERIFIER.ru.md.

В worker_debug.json найдено точное расхождение: в источнике есть обратные кавычки вокруг `worker.py`, а Qwen убрал их в цитате. Обе попытки отклонены. Правильный документ уже был первым результатом, поэтому изменение min_similarity не требуется.

Теперь приложение создаёт каталог дословных фрагментов выбранных чанков. Модель выбирает `chunk_id` + `quote_id` из enum в JSON Schema. Приложение извлекает исходный текст и проверяет его принадлежность чанку. Выходной JSON по-прежнему содержит `answer`, `sources`, `quotes`, `claims`; quotes дополнительно сохраняют `quote_id`. Свободный текст цитат в production draft не принимается.

Это устраняет зависимость дословности от перепечатывания Markdown моделью. Проверка смысла остаётся отдельной: правильный ID не делает ложное утверждение правильным. Verifier должен подтвердить каждое утверждение и полноту ответа. Он также может ошибаться; ручная проверка необходима.

`validation.model_calls` теперь содержит исходные draft/verifier ответы. `retrieval.quote_catalog` содержит каталог, по которому можно расшифровать IDs. Смысловые ошибки и исправления сохраняются в diagnostics.

## Применение

Распакуйте архив в корень существующего проекта, заменив файлы папки `day-24-citations-grounding/`. В ZIP находится только эта папка. Старые модели, настройки, корпус и knowledge.db сохраняются. Пересобирать индекс для этого исправления не требуется: файлы новых RAG-уроков не входят в корпус, корневые README в патче отсутствуют.

```bash
python day-24-citations-grounding/test_day24.py -v
```

Ожидается: 28 тестов и OK. Затем повторите обычную проверку:

```bash
python day-24-citations-grounding/main.py ask \
  "Which process periodically collects GitHub repository snapshots into SQLite on Day 18?" \
  --output day-24-citations-grounding/reports/check/worker_fixed.json
```

Ожидаемый смысл: независимый worker.py выполняет периодический сбор и сохраняет GitHub-снимки в SQLite. Для принятого ответа нужны status=answered, непустые sources/quotes и все три флага validation=true. Точный смысловой результат Qwen после патча ещё предстоит проверить локально.

Если снова получен unknown, пришлите worker_fixed.json: отдельный debug-скрипт больше не нужен.

В среде подготовки выполнены 28 тестов Дня 24 и 34 регрессионных теста прежних дней, плюс контролируемый replay 10 положительных примеров и 2 отказов. Это не живой прогон новой версии Qwen.
