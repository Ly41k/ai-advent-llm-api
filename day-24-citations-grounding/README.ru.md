# День 24 — цитаты, источники и анти-галлюцинации

RAG Дня 24 использует индекс Дня 21 и поиск Дня 23. Текущий протокол — `verbatim-extractive-v14`: модель выбирает фрагменты найденных чанков, а приложение собирает ответ, источники и дословные цитаты. При недостаточном контексте возвращается «не знаю» с просьбой уточнить вопрос.

Ответ сохраняет исходный язык фрагментов; он может включать код, таблицу или диаграмму. Это извлечение текста источников, поэтому свободное объяснение или перевод не являются поведением по умолчанию.

## Проверенный результат задания

В репозитории сохранён полный живой диагностический прогон на Mac M1 с 32 ГБ памяти, Python 3.13.3, `bge-m3` и `qwen2.5:14b`. Для выбора цитат и проверки покрытия использовалась 14B-модель.

| Требование | Результат сохранённого прогона v14 |
|---|---|
| Проверка на 10 вопросах | 10 содержательных ответов |
| Источники: `source` + `section` / `chunk_id` | Есть в каждом из 10 ответов |
| Цитаты из найденных чанков | Есть в каждом ответе; 53/53 цитаты дословные |
| Смысл ответа и полнота относительно вопроса | 10/10 подтверждены последующим разбором источников ассистентом |
| Автоматическая модельная оценка покрытия вопроса | 7/10; отрицательные оценки 01, 03 и 05 сохранены |
| «Не знаю» и уточнение | 2/2 отрицательных контрольных вопроса; отдельно показан отказ при пороге 0.99 |

Доказательства: [разбор всех вопросов](reports/live/REVIEW_evaluate_v14.ru.md), [исходный JSON](reports/live/evaluate_v14_original.json), [JSON с ручной проверкой](reports/live/evaluate_v14_reviewed.json). В разборе также сверены 46 выбранных чанков с каноническим корпусом Дня 21.

Это результат **конкретного прогона** и проверки ассистентом, а не независимая человеческая оценка или автоматическое качество 10/10. В исходном отчёте `summary.assignment_complete=false`: проверка смысла ещё ожидалась. После разбора добавлен `manual_summary.assignment_complete=true`; исходные оценки и решения остались неизменными. Повторный консольный прогон сохранён в [original](reports/console/evaluate_again_original.json) и [reviewed](reports/console/evaluate_again_reviewed.json).

## Как обеспечиваются источники и цитаты

1. Поиск `rewrite_filter` получает кандидатов из общей базы знаний. Порог применяется **включительно**, до ограничения `final-k`.
2. Приложение создаёт каталог фрагментов найденных чанков. Модель выбирает известные `quote_id`, а не придумывает текст цитат.
3. Приложение проверяет ID, исходный текст и принадлежность найденному чанку; берёт путь и раздел из метаданных индекса и вычисляет строки цитаты. Каждое опубликованное утверждение совпадает со своей цитатой. Консольная демонстрация дополнительно сверяет цитаты с текущими локальными файлами.
4. Модельный аудитор оценивает покрытие вопроса выбранными фрагментами через `proof_ids`. Результат проверки сохраняется, включая отрицательные оценки и ошибки.
5. Выбранная политика определяет, можно ли публиковать ответ или следует отказать.

| Поле результата | Что показывает |
|---|---|
| `status`, `answer` | Содержательный ответ или отказ |
| `sources` | `source`, `section`, `chunk_id`, границы строк, cosine и ID источника |
| `quotes` | Дословный текст, `quote_id`, связь с утверждением и источником, границы строк |
| `claims` | Утверждения и привязанные к ним цитаты |
| `clarification`, `reason` | Уточнение и причина отказа |
| `validation` | Проверки источников, цитат, покрытия, политика и исходные ответы модели |
| `retrieval` | Параметры поиска, кандидаты и выбранные чанки |

Дословное совпадение доказывает происхождение текста, но само по себе не доказывает релевантность, полноту или истинность источника. Поэтому для выполнения задания нужно проверить смысл каждого из 10 ответов.

## Две политики проверки покрытия

| Политика | Поведение |
|---|---|
| `strict` — по умолчанию | Публикует только ответ с проверенными источниками и положительной модельной проверкой покрытия. После ограниченных попыток исправления неподтверждённый ответ заменяется отказом. |
| `diagnostic` — включается явно | Может публиковать дословные проверенные фрагменты при отрицательной или неудачной оценке покрытия. Сохраняет отрицательный результат и отмечает необходимость ручной проверки. |

В обоих режимах неверные ID, подменённые цитаты и свободный текст модели блокируются. В диагностическом режиме `contract_pass` проверяет контракт ответа/источников/дословных цитат; он **не означает**, что модель подтвердила полноту. Поля `coverage_supported`, `manual_review_required`, `contract_includes_model_coverage` и сводка отчёта позволяют увидеть это различие.

Для нового прогона проверьте **все 10 ответов**, даже если модель приняла часть из них. До отдельного разбора `assignment_complete` остаётся `false`. Проверяйте наличие источников и цитат, связь каждой цитаты с найденным чанком, смысл ответа, полноту и роли участников описанного процесса. `expected_terms` и попадание в ожидаемый документ не заменяют такую проверку.

В извлекающем режиме прежний смысловой verifier для свободного пересказа не вызывается: `semantic_verifier_used=false`, а `positive_semantic_verifier_pass=0` ожидаем. Проверку покрытия отражает `positive_coverage_pass`. Исторический `--answer-style paraphrase` включается отдельно и несовместим с `diagnostic`.

## Подготовка на вашем Mac

Все команды запускайте **из корня репозитория**, с активированной `.venv`. День 24 использует стандартную библиотеку Python и модули дней 21 и 23; ключ Groq для него не нужен.

```bash
source .venv/bin/activate
ollama list
```

В вашем окружении уже установлены `bge-m3` и `qwen2.5:14b`. Другие установленные модели удалять для этой работы не требуется. Если нужных моделей нет:

```bash
ollama pull bge-m3
ollama pull qwen2.5:14b
```

Ollama должен обслуживать `http://127.0.0.1:11434`. Если приложение Ollama уже запущено, отдельный `ollama serve` не нужен.

| Параметр | Значение по умолчанию |
|---|---|
| База знаний | `day-21-document-indexing/knowledge.db` |
| Эмбеддинги / выбор цитат | `bge-m3` / `qwen2.5:14b` |
| Аудитор покрытия | Та же модель; другая задаётся через `--verifier-model` |
| Стратегия / rewrite | `fixed` / `heuristic` |
| Кандидаты / итоговый контекст | `20` / `5` чанков |
| Порог raw cosine | `>= 0.50` |
| Стиль / политика | `extractive` / `strict` |
| Контекст / лимит генерации | `16384` / `2500` токенов |
| Температура / HTTP timeout | `0` / `600` секунд |

Для нового живого запуска нужна актуальная база. Если она отсутствует или `verify` обнаруживает устаревший индекс:

```bash
python day-21-document-indexing/main.py build
python day-21-document-indexing/main.py verify
```

**Корневые README входят в индексируемый корпус.** После замены этих файлов и после нового коммита пересоберите индекс в окончательной версии checkout и выполните `verify`. Новые scores и ответы могут измениться; сохранённые отчёты описывают прежний прогон. Для просмотра сохранённой консольной демонстрации база и Ollama не нужны.

## Один вопрос и полный набор

Глобальные флаги ставятся **до** `ask` / `evaluate`. Следующий пример явно выбирает диагностическую политику сохранённого проверенного прогона:

```bash
python day-24-citations-grounding/main.py --coverage-policy diagnostic \
  ask "Which process periodically collects GitHub repository snapshots into SQLite on Day 18?" \
  --output day-24-citations-grounding/reports/check/worker.json

python day-24-citations-grounding/main.py questions

python day-24-citations-grounding/main.py --coverage-policy diagnostic \
  evaluate --output day-24-citations-grounding/reports/check/evaluate.json
```

`questions.json` содержит 10 положительных вопросов и 2 отрицательных контроля. `ask` выводит полный JSON; `evaluate` сохраняет JSON с подробностями каждого ответа и Markdown рядом с ним. Для строгого режима уберите `--coverage-policy diagnostic`.

Для `evaluate` код выхода `0` означает прохождение автоматического контракта выбранной политики; в диагностическом режиме ручная проверка всё ещё нужна. Код `1` означает провал проверок с сохранённым отчётом, `2` — техническую ошибку или ошибку настройки. Отдельная команда `ask` не выполняет сводную оценку набора.

## Как показать режим «не знаю»

| Сценарий в сохранённых данных | Результат |
|---|---|
| `negative-02`: вопрос об орбитальной скорости, max cosine ≈ 0.423 < 0.50 | `below_threshold`, «не знаю», уточнение, 0 выбранных чанков и 0 структурированных вызовов модели |
| `negative-01`: вопрос о выручке, max cosine ≈ 0.520 >= 0.50, но фактов нет | `insufficient_context`, отказ и уточнение без выдуманных источников |
| Вопрос о worker при временном пороге 0.99, max cosine ≈ 0.594 | `below_threshold`, отказ и уточнение, 0 выбранных чанков и 0 структурированных вызовов модели |

```bash
python day-24-citations-grounding/main.py --coverage-policy diagnostic \
  --min-similarity 0.99 \
  ask "Which process periodically collects GitHub repository snapshots into SQLite on Day 18?" \
  --output day-24-citations-grounding/reports/check/threshold_check.json
```

Порог `0.99` нужен для наглядного эксперимента с тем же вопросом; рабочий default остаётся `0.50`. Подберите рабочий порог для своего индекса по процедуре Дня 23. Точный score после пересборки может отличаться.

У отказа `sources`, `quotes` и `claims` пустые: отсутствие ответа не нужно прикрывать фиктивными доказательствами. Текст отказа и уточнение следуют языку вопроса. При пороговом отказе нулевое число вызовов относится к стандартному `heuristic` rewrite; `llm` rewrite может потребовать отдельный вызов. Ошибки HTTP или эмбеддингов остаются техническими ошибками и не маскируются под «не знаю».

## Видео целиком через консоль

```bash
# Просмотр сохранённого реального прогона с паузами Enter:
python day-24-citations-grounding/console_demo.py

# Новый живой прогон через локальный Ollama:
python day-24-citations-grounding/console_demo.py --live
```

Первый режим явно обозначен как просмотр отчётов. Он выводит все ответы, полные цитаты, `source` / `section` / `chunk_id`, проверку строк локальных файлов, исходную модельную оценку 7/10 и записанную ручную проверку 10/10. `--no-pause` выводит всё без остановок.

`--live` получает новые ответы с 14B-моделью и диагностической политикой. Сохраняет `reports/check/console_live.json`, Markdown, отдельные ответы в `console_live_answers/` и `console_live_threshold.json`. Старые ручные оценки не переносятся; Enter только переключает экран. Существующие выходные файлы не перезаписываются: для повторного запуска задайте новые `--report` и `--threshold-report`.

На видео обратите внимание на режим запуска, реальные поля источников, дословные цитаты, различие между контрактом и смысловой полнотой, отрицательные оценки аудитора и оба вида отказа. Покажите сравнение рабочего порога 0.50 и экспериментального 0.99. Подробный сценарий: [CONSOLE_VIDEO.ru.md](CONSOLE_VIDEO.ru.md).
