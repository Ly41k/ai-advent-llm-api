## Что исправлено

- Ответ ограничен 1–3 утверждениями. Генератор должен объяснять запрошенный механизм или шаги, а не перечислять возможности, побочные детали и примеры диалогов. Repair возвращает краткую замену старого ответа.
- Простые ASCII-идентификаторы, явно отмеченные обратными кавычками, проверяются по цитатам своего утверждения. Название сервиса `bublik-day18` больше не проходит на общем абзаце про systemctl/journalctl. Проверяется полное имя, а не сходный префикс. Namespace перед методом допустим; путь источника может подтвердить имя Python-файла, но не имя функции/сервиса.
- Если ответ называет метку диаграммы отдельным состоянием, локальная проверка ищет явную Markdown enum-таблицу state/stage в цитируемом чанке. Найденное перечисление ограничивает трактовку меток переходов. Для присланного ответа fail отсутствует в enum и утверждение отклоняется. Список состояний извлекается из источника, не зашит в код. Проверка намеренно узкая и не является полноценным разбором диаграмм или естественного языка.
- Verifier явно разделяет истинность каждого утверждения и полноту общего ответа. Неполный, но истинный schema-факт не должен становиться ложным только потому, что один он не отвечает на весь вопрос.

Порог, источники и модели прежние. Обязательные цитаты, смысловой verifier, отказ при слабом контексте и лимит двух draft-попыток сохраняются. Ничего из эталонных ответов или ручного отчёта production-модели не передаётся.

## Применение и экономная проверка

Архив содержит всю актуальную папку Дня 24 с предыдущими исправлениями и отчётами. Распакуйте в корень проекта с заменой её файлов. Индекс пересобирать не нужно.

```bash
python day-24-citations-grounding/test_day24.py -v
python day-24-citations-grounding/main.py evaluate \
  --questions day-24-citations-grounding/questions_recheck.json \
  --output day-24-citations-grounding/reports/check/recheck_v3.json
```

Ожидается 40 тестов и OK. questions_recheck.json содержит четыре исходных вопроса: 01, 02, 09, 10. Это промежуточная проверка, не полный итог задания. Протокол в новых результатах должен быть `quote-ids-grounding-v3`.

Ожидаемый смысл:

| Вопрос | Нужный ответ и доказательства |
|---|---|
| 01, диалоги | Уникальный UUID/conversation_id ограничивает сообщения выбранного диалога; SQLite сохраняет их и загружает выбранную историю после запуска. Нужны цитаты правил, а не только сценарий Аврора/Ремонт. |
| 02, FSM | Четыре состояния из явного state enum. fail на стрелке — результат проверки/перехода, а не пятое состояние. |
| 09, orchestration | Маршрут github → analysis → storage → read → verify, сравнение сохранённого текста с исходной сводкой. Имя verify_report и правило сравнения должны присутствовать в цитатах соответствующего claim. |
| 10, VPS | Реальные status/journalctl команды с bublik-day18 и наблюдение свежей сохранённой сводки после выполнения расписания. Цитировать команды и описание чтения свежих результатов. |

Принятый ответ: status=answered, источники/цитаты непусты, три validation-флага=true. Затем просмотрите смысл каждого ответа: модельный положительный verdict остаётся ненадёжным без ручной сверки.

После успешной целевой проверки выполните полный набор 10 + 2:

```bash
python day-24-citations-grounding/main.py evaluate \
  --output day-24-citations-grounding/reports/check/evaluate_final.json
```

Нужны 10 подтверждённых ответов и оба корректных отказа, без ложных состояний, нецитируемых имён или неподтверждённых условий. Код 1 сохраняет отчёт и означает непройденные проверки; код 2 означает техническую ошибку.
