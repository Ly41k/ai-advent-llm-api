# День 24 — всё для видео в консоли

Режим презентации добавлен к рабочей v14. Алгоритм RAG, модели, индекс и 15 исходных Python-файлов не менялись. Новые файлы: `console_demo.py` и `test_console_demo.py`. Протокол по-прежнему `verbatim-extractive-v14`.

## Установка

Из корня **существующего** репозитория в терминале VSCode:

```bash
unzip -o ~/Downloads/day24-console-demo-v14.zip -d .
source .venv/bin/activate
```

Архив обновляет только папку Дня24. Дни21–23, `.venv`, `.env`, модели и `knowledge.db` сохраняйте. Локальные `reports/check` архивом не заменяются. Индекс не пересоздавайте.

## Запись готового результата — одна команда

```bash
python day-24-citations-grounding/console_demo.py
```

Всё происходит в консоли; браузер и открытие Markdown/JSON не нужны. Скрипт выводит текст страницами по высоте терминала. **Enter** — следующая страница/экран, **Ctrl+C** — закончить. Увеличьте окно терминала, выберите читаемый размер шрифта. Скрипт не очищает предыдущий вывод: можно прокрутить назад.

Первый экран прямо сообщает: **просмотр сохранённого реального прогона**. Это не новая генерация в кадре. Используются предоставленные пользователем `evaluate_again.json` и `threshold_check.json`, а также отдельная reviewed копия полного отчёта. Все ответы и публичные доказательства нового полного отчёта совпали с проверенным v14; 53 цитаты и 46 чанков проверены отдельно. Ручная проверка выполнена ассистентом, не независимым человеком. Исходные модельные оценки не изменены.

При запуске скрипт заново проверяет цитаты против найденных чанков, каталога quote IDs и **реальных файлов текущего репозитория**: текст, строки, source metadata, связи утверждение→цитата→источник, отсутствие добавленного текста в публичном ответе. Если исходные файлы изменились и проверка не проходит, выводится FAIL; сохранённый результат не считается успешно воспроизведённым.

Для полного вывода без пауз, например чтобы сохранить журнал:

```bash
python day-24-citations-grounding/console_demo.py --no-pause \
  > day24-console-recording.txt
```

## Последовательность видео и акценты

1. **Введение.** «День24: ответ, источники и цитаты; отказ с уточнением при слабом контексте». Первый экран показывает режим просмотра отчётов, затем фактические настройки из отчёта: bge-m3, qwen2.5:14b, fixed, candidate20/final5, diagnostic.
2. **Каждый вопрос.** Видны ID, полный вопрос, ориентир для проверки, max cosine, порог, число кандидатов и выбранных чанков.
3. **Ответ.** Покажите status/reason и полный исходный ответ. Скрипт не сокращает и не переписывает ответы модели.
4. **Источники.** Остановитесь на `source`, `section`, `chunk_id`, строках и ссылках `[1]`, `[2]`. Это обязательные реквизиты задания.
5. **Цитаты.** Каждая цитата выведена полностью вместе с ID утверждения и источника. На экране проверок видно, что её дословность и связи проверены кодом. Смысл и полнота не выводятся из совпадения текста автоматически: рядом показана запись ручной проверки и исходная оценка аудитора.
6. **Положительные01–10.** Пройдите все десять. Для 01 покажите SQLite, conversation_id/UUID и восстановление выбранного диалога; для 03 — preflight/postflight; для 05 — initialize/list_tools. Их модельный verdict=false остаётся видимым, ручная оценка объяснена отдельно.
7. **Вопрос09.** Покажите обе части: маршрутизацию github/analysis/storage и read_report→verify_report, сравнение с исходной сводкой, успех после verified=true.
8. **Вопрос10.** Проверка периодичности — не только service active: нужны повторные запуски / свежие сводки. В цитате есть вывод после каждого запуска и проверка журнала/сводки.
9. **negative-01, выручка.** max cosine≈0.52024, выше рабочего0.50, но факта о выручке нет. insufficient_context, «не знаю»/I don't know, уточнение, пустые sources/quotes. Ассистент не придумывает сумму.
10. **negative-02, орбита.** max cosine≈0.42301 ниже0.50, reason=below_threshold, русское «не знаю», уточнение,0 выбранных чанков и0 model calls. Это усиление задания на рабочем пороге.
11. **Отдельный threshold experiment.** Тот же вопрос о worker, что positive-07, но временный порог0.99. Max cosine≈0.59395 ниже0.99: отказ+уточнение,0 выбранных чанков,0 вызовов модели. 0.99 — только контролируемый эксперимент, рабочий порог остаётся0.50.
12. **Итог.** Ответы и источники/цитаты10/10,53 точных цитаты; модельный аудит7/10; сохранённая ручная проверка смысла и полноты10/10; контрольные отказы2/2, оба теста порога PASS. Исходный assignment_complete=false сохраняется. Итог после ручной проверки относится к показанному отчёту, не к любому будущему запросу.

Не нужно зачитывать каждую длинную цитату. Покажите все экраны, а голосом отмечайте прямые доказательства и результаты проверок. Текст из code/diagram/table остаётся на исходном языке; возможны дубли и обрывки на границах чанков. Это существующие свойства v14, презентация их не скрывает.

## Если требуется именно новая генерация в кадре

Запустите Ollama заранее. Всё отображается по мере получения ответов, без отдельного JSON-редактора:

```bash
python day-24-citations-grounding/console_demo.py --live
```

Новый прогон использует тот же StrictRAGAgent с **явной diagnostic policy**, модели bge-m3/qwen2.5:14b, ctx16384, output2500, timeout600, рабочий порог0.50 и эксперимент0.99. Может занять значительно больше времени, чем просмотр готового прогона. Пока работает модель, видны этапы selector/coverage; паузы Enter только между экранами.

Результаты сохраняются в `reports/check/console_live.json`, `.md` и `console_live_threshold.json`. Каждый завершённый ответ дополнительно сохраняется до пауз в `reports/check/console_live_answers/`. При Ctrl+C завершённые ответы доступны, но итоговый полный отчёт может ещё отсутствовать. Ошибки Ollama/индекса показываются как ошибки, а не как «не знаю».

Существующие отчёты/папка checkpoints не перезаписываются. Для ещё одного запуска задайте новые имена:

```bash
python day-24-citations-grounding/console_demo.py --live \
  --report day-24-citations-grounding/reports/check/console_live_2.json \
  --threshold-report day-24-citations-grounding/reports/check/console_live_2_threshold.json
```

Новый отчёт требует ручной проверки всех новых ответов. На итоговом экране будет **«ручная проверка не заполнена»**, даже если источники/цитаты10/10 и модельный coverage10/10. Прежний manual10/10 автоматически не переносится. Пауза Enter означает только переход к следующему экрану, не подтверждение правильности.

## Просмотр своих файлов

```bash
python day-24-citations-grounding/console_demo.py \
  --report day-24-citations-grounding/reports/check/evaluate_again.json \
  --threshold-report day-24-citations-grounding/reports/check/threshold_check.json
```

Скрипт показывает именно переданные файлы и их записанные оценки. Если в исходном JSON manual_review=null, завершение ручной проверки не заявляется. Для записи подтверждённого результата используйте первую команду без параметров: reviewed копия ваших файлов уже включена в архив.
