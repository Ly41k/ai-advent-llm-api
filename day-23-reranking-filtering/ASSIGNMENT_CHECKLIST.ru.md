# День 23 — повторная сверка каждого требования

| Требование задания | Реализация | Проверка |
|---|---|---|
| Второй этап после поиска | `rag23.select_hits()` получает уже найденные кандидаты | SQLite integration и тест порядка этапов |
| Reranker **или** фильтр релевантности | Выбран разрешённый фильтр по raw cosine similarity | `test_threshold_is_inclusive_raw_cosine_before_final_k` |
| Порог отсечения | `Settings.min_similarity`, CLI `--min-similarity` | Включительная граница, значение ниже порога, NaN/Inf, диапазон |
| Top-K до фильтрации | `candidate_k=20`, CLI `--candidate-k` | Поиск получает заданное число кандидатов; trace хранит весь пул |
| Top-K после фильтрации | `final_k=5`, CLI `--final-k` | Фильтр применяется до среза, итог не больше final-K |
| Меньше K релевантных результатов | Возвращается только найденное количество | Тест двух кандидатов и одного оставшегося |
| Все результаты нерелевантны | Пустой контекст → отказ без answer LLM | `test_empty_context_never_uses_llm_or_rejected_hits` |
| Не возвращать отброшенный шум для заполнения K | Нет fallback на rejected candidates | Тест пустого контекста и integration-проверка prompt |
| Query rewrite | Общий словарь или отдельный LLM-вызов | Сохранение исходного вопроса/номеров/identifiers, LLM один раз |
| Генерация отвечает на исходный вопрос | Rewrite используется только при поиске | Проверка всех generation-prompts |
| Качество без фильтра и rewriting | Режим `baseline` | `compare` и `evaluate` включают baseline |
| Качество с фильтром | Режим `filter` | Парное сравнение с тем же кандидатом-пулом |
| Отдельно увидеть эффект rewrite | Режим `rewrite` | Дельта `rewrite_minus_baseline` |
| Улучшенный RAG: rewrite + фильтр | Режим `rewrite_filter` | Дельты к baseline и rewrite |
| Честное сравнение режимов | Одна модель, одинаковый prompt, temperature=0 | HTTP integration и тест одинакового prompt |
| Настройка порога | `quality.calibrate()` перебирает пороги на 8 calibration-вопросах | Кэш кандидатов, защита от потери calibration-evidence |
| Не выбирать порог по тестовому набору | 12 evaluation-вопросов отделены от calibration | Тест исключает holdout query из вызовов провайдера |
| Проверка нерелевантных запросов | Четыре out-of-corpus вопроса, две отдельные выборки | Negative abstention и положительные false-rejection метрики |
| Сохранение сравнения | JSON + Markdown | Полный CLI → HTTP → SQLite → отчёты |
| Объяснимость фильтра | Score, source, lines, decision для каждого кандидата | `below_threshold`, `final_k_limit`, `selected` |
| Метрики качества | Source hit/precision/MRR, отрицательный отказ, потеря положительного контекста, термины | Арифметика отчёта и дельт проверена тестом |
| Проверка смысловой правильности | Ожидания и пустые `human_review` поля | Требует ручного просмотра реальных ответов; автоматические термины не заменяют его |
| Переиспользование Дней 21–22 | Общий Day 21 индекс и Ollama adapter; дизайн Day 22 | Модель/dimension проверяются; регрессии Дней 21–22 проходят |
| Архив для скачивания | Полный исходный репозиторий с Днём 23, RU/EN инструкциями и отчётами | Повторная проверка после извлечения архива |

Все программные пункты реализованы и проверены. Дополнительно пользователь выполнил реальные прогоны `bge-m3` с `llama3.2` и `qwen2.5:7b`; полученные JSON проверены в среде подготовки. Итоговая [сверка с результатами и ограничениями](LIVE_VERIFICATION.ru.md) содержит просмотр ответов и различает исходную калибровку 0.55 и исследовательскую настройку 0.50 после просмотра evaluation. Включённые `reports/offline_*` остаются отдельным лексическим сравнением и не выдаются за результаты Ollama.
