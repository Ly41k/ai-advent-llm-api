# День 23 — итог реальной проверки

Проверено по отчётам, полученным пользователем на Mac через локальный Ollama 30 сентября — 1 октября 2026 года. Модельные запуски выполнялись на компьютере пользователя; в среде подготовки архива проверены их данные, исходники и автоматические тесты. Оригинальные JSON сохранены без изменения в `reports/live/`.

## Проверенный профиль

- Embeddings: `bge-m3`, 1024 измерения.
- Генерация: `qwen2.5:7b`, общий prompt и temperature=0 для всех режимов.
- Chunking: `fixed`, размер 500 единиц, overlap 75. Это единицы индексатора, а не гарантированное число токенов LLM.
- Поиск: candidate-K=20. После фильтрации: не более final-K=5.
- Фильтр: включительный порог **raw cosine >= 0.50** до ограничения final-K.
- Rewrite: `heuristic`; исходный вопрос сохраняется для генерации.
- Индекс: `7e5cc6d6a75306eac586f51e62a0d0592c423c40@350a65b38804aaa6`, fixed built_at `2026-09-30 20:21:01`.
- В проверке 12 evaluation-вопросов: 10 с ответом в корпусе и 2 вне корпуса.

Профиль передаётся явно через CLI. Программные значения по умолчанию сохранены; одна команда без флагов не воспроизводит этот профиль.

## Сравнение режимов при пороге 0.50

| Метрика | baseline | filter | rewrite | rewrite_filter |
|---|---:|---:|---:|---:|
| Попадание ожидаемого документа на 10 полезных вопросах | 10/10 | 10/10 | 10/10 | 10/10 |
| Средняя точность источников на полезных вопросах | 28.0% | 30.3% | 30.0% | 37.3% |
| MRR | 0.791667 | 0.791667 | 0.766667 | 0.766667 |
| Полезные вопросы с пустым контекстом | 0/10 | 0/10 | 0/10 | 0/10 |
| Вопросы вне корпуса с пустым контекстом | 0/2 | 1/2 | 0/2 | 1/2 |
| Среднее число выбранных чанков на всех 12 вопросах | 5.00 | 4.00 | 5.00 | 3.83 |
| Среднее число слов контекста на всех 12 вопросах | 2007.8 | 1592.8 | 1851.8 | 1393.3 |
| Среднее покрытие ожидаемых терминов на полезных вопросах | 0.85 | 0.90 | 0.70 | 0.70 |

`rewrite_filter` относительно `rewrite`: точность источников +7.3 процентного пункта, объём контекста −24.8%, документный recall сохранён. Относительно baseline: точность +9.3 пункта, контекст −30.6%. В `filter` ответ об инвариантах теперь упоминает preflight и postflight, тогда как baseline описывает только postflight.

Это улучшение отбора контекста на данном наборе. **Покрытие терминов 0.90 не означает 90% правильных ответов. Попадание документа 10/10 не означает 10 правильных ответов.** Метрики используют размеченные документы, а не экспертную оценку каждого пассажа. Rewrite на этом наборе не даёт общего улучшения ответов: MRR и покрытие терминов ниже baseline.

На вопрос о выручке при 0.50 остаётся один нерелевантный чанк, но Qwen корректно отказывается отвечать. На медицинском вопросе фильтр оставляет пустой контекст и генерация не вызывается. Нулевой `negative_abstention_rate` у baseline обозначает наличие контекста, а не отсутствие смыслового отказа: baseline тоже отказался на обоих вопросах. В его медицинском отказе при этом есть лишняя ошибочная расшифровка MCP.

## Калибровка и ограничения эксперимента

Изначальная калибровка на отдельной группе из 8 вопросов выбрала **0.55** и для structural, и для fixed. Полный sweep калибровки не был загружен; доступны настройки и итог выбора из консольного вывода. Эти сведения не выдаются за полный файл калибровки.

При fixed/0.55 фильтр теряет контекст для 1/10 полезных вопросов, rewrite_filter — для 2/10. Для разговорного вопроса о worker максимум cosine=0.5360; для вопроса об инвариантах после rewrite — 0.5293. Поэтому 0.55 недостаточно хорошо переносится с маленькой calibration-группы на evaluation.

**0.50 выбран после просмотра evaluation-результатов.** Это исследовательская настройка на уже просмотренном наборе, а не независимое подтверждение на свежем holdout. Чтобы подтвердить перенос результата, нужно зафиксировать этот профиль и оценить новые вопросы, не подбирая по ним параметры.

Замена генерации `llama3.2` на Qwen заметно улучшила конкретные ответы при совпадающих кандидатах поиска. Это отдельный эффект модели генерации; он не приписывается фильтру. Диагностика окна 16384 не улучшила ответ llama3.2, переход на chat и один реальный чанк тоже не дали надёжного ответа. В архиве исходный общий генератор сохранён: успешные Qwen-прогоны выполнены через существующий CLI.

## Воспроизведение

Из корня существующего checkout с готовым чистым индексом:

```bash
python day-23-reranking-filtering/main.py \
  --answer-model qwen2.5:7b \
  --strategy fixed \
  --candidate-k 20 \
  --final-k 5 \
  --min-similarity 0.50 \
  evaluate \
  --output day-23-reranking-filtering/evaluate_fixed_qwen_050_results.json
```

Если профиль переносится на другой корпус или embedding-модель, порог нужно заново калибровать. Архив не содержит моделей Ollama, `.venv`, секретов или SQLite-индекса. Если индекс уже построен с исправленным `corpus.py` и тем же корпусом, повторная сборка для добавленных отчётов не нужна: они исключены из индексируемых источников.
