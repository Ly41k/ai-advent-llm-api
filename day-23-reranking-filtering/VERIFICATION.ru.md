## Что показывает включённое сравнение

`reports/offline_comparison.json` и `.md` — retrieval-only сравнение **лексического** TF-IDF hash embedder на реальных файлах. Порог выбран только по восьми calibration-вопросам; качество измерено на двенадцати отложенных.

В этом примере rewrite увеличивает попадание размеченного источника относительно baseline, а выбранный фильтр снижает recall на отложенных вопросах. Это сохранено в отчёте. Калибровочное ограничение не гарантирует перенос качества на holdout, особенно при маленьком наборе. Результат демонстрирует необходимость смотреть одновременно на шум, полезные источники и ложные отказы.

Это не проверка `bge-m3`/`llama3.2`, и порог лексической модели нельзя применять к ним. В среде подготовки не было запущенного Ollama с этими моделями. Реальные ответы не имитировались, поля human review не заполнялись автоматически.

## Реальная модельная проверка на Mac

```bash
source .venv/bin/activate
ollama pull bge-m3
ollama pull llama3.2
python day-21-document-indexing/main.py build
python day-21-document-indexing/main.py verify
python day-23-reranking-filtering/main.py calibrate
# Подставить selected_threshold вместо примерного 0.25:
python day-23-reranking-filtering/main.py --min-similarity 0.25 evaluate
```

Проверить `evaluate_results.json`: ответы, источники и контекст во всех четырёх режимах, затем заполнить human-review поля. Отдельная [сверка каждого пункта задания](ASSIGNMENT_CHECKLIST.ru.md) приложена.
