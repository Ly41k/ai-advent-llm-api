# Исправление временных путей macOS — v0.2.1

На Mac сборка индекса, проверка источников и поиск прошли. При запуске
`check_stage3.py` 28 тестов остановились в общей подготовке временного хранилища:
`ProjectState` запрещает ссылки в пути, а системный временный каталог macOS
может быть доступен через `/var`, который ссылается на `/private/var`.

Тестовая фикстура и временное хранилище проверочного скрипта теперь используют
физический путь созданного каталога (`resolve(strict=True)`). Проверка рабочего
хранилища не изменена. Добавлен тест, который проверяет отказ для ссылки в пути
хранилища до создания вложенного каталога.

Распакуйте `day31-mac-temp-fix.zip` в корень репозитория с заменой файлов.
Это обновление поверх установленной версии v0.2.0; зависимости прежние.
Пересобирать уже проверенный индекс не требуется.

Запустите из корня репозитория с активированной `.venv`:

```bash
python -W error::ResourceWarning day-31-developer-assistant/scripts/check_stage3.py --output /tmp/day31-stage3-mac-v021.json
```

Ожидается 73 теста, `OK` и `status: passed` в новом JSON-отчёте.
Скрипт не перезаписывает существующий файл отчёта: при повторном запуске
укажите новое имя.

На Linux с Python 3.13 проверены обычный временный путь и путь через специально
созданную ссылку в `TMPDIR`: в обоих случаях прошли 73 теста и проверка реального
FTS-индекса (40 документов, 376 фрагментов). Это проверка причины сбоя,
а не подтверждение успешного повторного запуска на Mac. Реальный bge-m3,
Qwen и жизненный цикл агентов здесь ещё не проверены.
