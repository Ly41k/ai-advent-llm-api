# Отбор содержательных фрагментов — v0.2.3

В реальном hybrid поиске v0.2.2 первые два из трёх результатов содержали только
заголовки. Они были корректными цитатами источника, но не объясняли устройство
памяти и занимали места в ограниченном контексте.

В v0.2.3 Markdown-фрагменты, состоящие только из ATX-заголовков (`#`–`######`)
и пустых строк, исключаются из FTS и dense до ограничения candidate-k.
Hybrid объединяет ранги уже отфильтрованных кандидатов. Schema text и code
fences остаются доступны. Этот фильтр не доказывает смысловую релевантность
остальных фрагментов. Setext-заголовки здесь не классифицируются.

Версия политики `markdown-body-v1` и число исключённых фрагментов возвращаются
в settings/content_filter и сохраняются в калибровочном отчёте. Индекс, векторы,
chunk IDs, исходные цитаты и координаты не изменяются. Корпус также прежний.
Поэтому уже собранный индекс 40 docs / 376 chunks используется без пересборки.

## Зафиксированный Mac baseline v0.2.2

12 retrieval-only calibration cases: 10 положительных, 2 отрицательных.

| Режим | Source/keyword hit@5 | Source MRR | Пустые отрицательные | Медиана поиска |
|---|---:|---:|---:|---:|
| FTS | 10/10 | 0.90 | 2/2 | 0.078 s |
| Dense | 9/10 | 0.80 | 2/2 | 1.896 s |
| Hybrid | 10/10 | 0.85 | 2/2 | 1.882 s |

Источник: неизменённый пользовательский отчёт
`reports/verified/retrieval-mac-v022-baseline.json`. Dense не нашёл ожидаемый
фрагмент для вопроса об Ollama API /ps как свидетельстве idle. FTS пока лучше
hybrid по MRR. Эти показатели не оценивают ответы Qwen и не являются финальным
held-out golden set; политика выбрана после наблюдения baseline.

## Проверка v0.2.3 на Mac

Полный архив распаковать из корня репозитория через терминал:

```bash
unzip -o ~/Downloads/day31-full-v023.zip -d "$PWD"
python day-31-developer-assistant/main.py index verify
python day-31-developer-assistant/main.py search "Как устроена память Бублика?" --mode hybrid --final-k 3
python -W error::ResourceWarning day-31-developer-assistant/scripts/check_stage3.py --output /tmp/day31-stage3-mac-v023.json
python day-31-developer-assistant/scripts/compare_project_retrieval.py --modes all --output /tmp/day31-retrieval-all-mac-v023.json
```

Ollama сохраняет подтверждённую выделенную сессию. Day 30 и другие Ollama clients
остаются отключёнными. Если сервер перезапущен отдельно, нужен прежний протокол
prepare → restart → confirm. Путь output должен быть новым.

Индекс не пересобирать. Ожидаются verified, содержательные цитаты и 78 тестов.
Изменение качества dense/hybrid устанавливается по новому реальному Mac отчёту,
а не предполагается заранее.

## Локальная проверка

78 тестов прошли на Linux/Python 3.13.16. Regression tests проверяют фильтрацию
до candidate-k=1 во всех режимах, отсутствие evidence при корпусе только из
заголовков, сохранение code/schema text, точных цитат/строк и CURRENT pointer.
Dense в unit tests использует явно синтетические векторы.

Ранее собранный реальный FTS-индекс успешно использован новой политикой без
пересборки: 10/10 hit@5, MRR 0.90, 2/2 пустых отрицательных запросов. Для
вопроса о памяти три возвращённых фрагмента содержат текст. Эти результаты
сохранены в reports/verified/fts-heading-filter-linux.json.
