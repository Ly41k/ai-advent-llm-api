# Короткое видео дня 25

Цель видео: показать рабочий CLI, свежий RAG, источники, память задачи и сохранение диалога. На Mac используются bge-m3 и qwen2.5:14b.

## Подготовка

Применить update-v22, выполнить единственный summary-вопрос из RELEASE_V22.ru.md и проверить JSON/ответ. Git HEAD пока не менять: после нового commit индекс будет stale по revision, и перед следующим чатом нужны build/verify дня 21. Обновление Day25/Day24 само по себе не меняет индексируемый корпус.

## Запись: 4–6 минут

1. Открыть `day-25-rag-chat/README.ru.md`: показать схему и отдельные базы history/knowledge.
2. В терминале запустить `python day-25-rag-chat/main.py chat`. Все команды с `/` ниже вводить внутри приглашения **You>**, не в zsh.
3. Ввести `/goal Разобраться в планировщике дня 18.`; `/constraint Worker должен работать отдельно от чата.`; `/term снимок=сохранённые данные GitHub`; `/state`. Показать сохранённую цель, ограничение и термин.
4. Обычный вопрос `Какой процесс выполняет фоновые задания на день 18?` — показать fresh search, ответ и Sources с путём/строками/chunk_id/cosine.
5. Обычный follow-up `А где хранятся снимки?` — показать ответ SQLite/schedule.db с источниками, затем `/state` и `/history`.
6. `/quit`, затем в shell снова `python day-25-rag-chat/main.py chat --session ID` с ID своей видео-сессии. `/state` и `/history` показывают сохранение после нового запуска процесса.
7. Открыть `reports/live/live-long-scenarios-v21-review.ru.md`: два реальных диалога по 12 ходов. История и task memory сохранены; 45 цитат точные; 23 ответа и один ложный отказ. Показать отдельно summary-route-v22.json после повторной проверки. Не называть исходный all_checks_pass=false полным PASS.

Снимать только фактически полученные ответы. Тестовые fixture не выдавать за живой Qwen. Запрошенная локальная база schedule.db не подключается как live data: чат отвечает по документам, а точное число локальных снимков должен честно отклонять.

## Публикация в свой GitHub после записи

Проверить изменения и добавить именно реализацию/документацию/проверенные отчёты. `.env`, базы и `.venv` исключены. reports/check игнорируется; если нужно опубликовать новый summary JSON, сначала скопировать его в reports/live с понятным именем. Не изменять исходный отчёт, чтобы сделать его зелёным.

```bash
git status --short
git add day-25-rag-chat day-24-citations-grounding/strict_agent.py README.md README.ru.md
git diff --cached --stat
git commit -m "feat: add Day 25 RAG chat with history and task memory"
git push
```

Этот документ — команды для пользователя; публикация из среды подготовки не выполнена. Полный solution-v22 архив содержит автономный снимок без `.git`, а update-v22 — обновление существующего checkout. Не заменять своим старым снимком всю рабочую репу с более новыми коммитами.

После commit для следующих запусков чата:

```bash
python day-21-document-indexing/main.py build
python day-21-document-indexing/main.py verify
```
