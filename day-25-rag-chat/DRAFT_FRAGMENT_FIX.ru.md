# v16 — Проверка целостности после сокращения черновика

## Живой результат

`long-detour-v15.json` пройден: отдельный worker и его команда, точные источники дня 18, полная память задачи дня 20 сохранена. `long-return-v15.json` не пройден: цель восстановлена и fresh RAG ищет день 20, но обе попытки selector выбрали лишнюю инструкцию установки q1_14 без следующего кода q1_15. Guard корректно запрещает публиковать такую инструкцию, но до v16 он также не давал refiner удалить её из черновика.

## Изменение

Структурно допустимый начальный набор из 2–6 точных ID может пройти один прежний вызов refiner, даже если содержит лишнюю intro. Это не ответ и не доказательство полноты. Начальная ошибка записывается в `validation.selection_refinements[].initial_fragment_errors`. Модель вправе только выбрать подмножество исходных ID; текст цитат, полный question/requirements и provenance не меняются.

Зависимости intro/code вычисляются по исходному каталогу, до фильтрации подмножества. Если нужный following code не входил в начальный набор, его нельзя добавить: модель должна удалить связанную intro или вернуть unknown. Фильтрация не создаёт новых соседей. Итоговая intro требует своего следующего кода непосредственно после неё. Если refiner оставляет orphan или добавляет ID, кандидат отклоняется до audit.

Guard неполных таблиц работает до первоначального выбора. Token-limit начального вызова нельзя спрятать успешным сокращением. Malformed/duplicate/forged/single-ID initial responses не получают новый путь обхода. Отрицательный coverage остаётся отрицательным, прежние две попытки кандидата и исходные модули дней 21–24 сохранены.

## Проверено

103 автоматических теста PASS; 2×12 scripted сценария входят в набор. Новые тесты покрывают удаление лишней intro, запрет добавления её unselected partner, сохранение полной исходной зависимости, отсутствие выдуманной смежности и token-limit. Интеграционные HTTP/SQLite тесты проверяют память, точный ответ, аудит полного вопроса и отказ при потере запрошенного описания registry. Это протокольные тесты с scripted моделью; настоящего Ollama здесь нет. Живое качество v16 и чистые 12+12 остаются неподтверждёнными.

## Повторить на Mac

Распакуйте архив в корень `ai-advent-llm-api` с заменой `day-25-rag-chat/`. Исправления v1–v16 включены. Пользовательские базы и `.env` исключены; индекс пересобирать не требуется.

```bash
python day-25-rag-chat/main.py ask \
"Вернёмся к нашей цели. Что делает mcp_registry.py?" \
--session 4fb98ce5a966406688e4d80b51cfa7ba \
--output day-25-rag-chat/reports/check/long-return-v16.json
```

Проверяем возврат к цели дня 20 без номера дня в вопросе, прямое описание регистрации/маршрутизации, точные источники, неизменную память и отсутствие orphan fragments. Наличие status=answered само по себе не завершает ручную проверку.
