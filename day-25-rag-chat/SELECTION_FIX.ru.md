# v13 — Минимальный полный набор цитат

## Подтверждённая проблема

В `long-info-v12.json` (сессия `4fb98ce5a966406688e4d80b51cfa7ba`, ход 55) текущий вопрос спрашивает только маршрут `--task info` дня 20. Источник прямо говорит: он вызывает только GitHub. Но selector также выбрал таблицу всех серверов и цепочку полного `report`; цепочка напечатана после правильного ответа без пояснения, что это другой маршрут. Все три цитаты дословны, память не изменилась и coverage=true. Ручная проверка ответа всё равно не пройдена: точность цитат не гарантирует уместность каждого фрагмента.

Оригинал сохранён без изменений в `reports/live/long-info-v12-original.json`; оценка — в `long-info-v12-review.json`.

## Исправление

После корректного первоначального выбора двух и более цитат выполняется один дополнительный компактный model call. Он получает текущий resolved question, все исходные requirements, точные тексты и provenance только первоначально выбранных цитат. История, цель и старые ответы в этот этап не передаются: первоначальный selector уже использовал их для понимания вопроса. Новая schema разрешает только подмножество выбранных ID; дополнительный локальный guard запрещает даже другие допустимые ID из полного каталога. Текст цитат не переписывается и не обрезается.

Затем прежние строгие валидаторы Day 24 и независимый coverage auditor проверяют результат по всему исходному вопросу. Если нужное доказательство удалено, отрицательный audit сохраняется; первоначальный ответ автоматически не возвращается. Есть прежние две попытки выбора нового кандидата, но отрицательный audit не повторяется ради одобрения. Если исходный selector вернул unknown, malformed, дубликаты, недопустимые ID или одну цитату, дополнительный этап не вызывается. Связь вводной строки с последующей командой проверяется до и после сокращения. Исчерпание token limit исходного selector не может быть скрыто новым вызовом.

В `validation.selection_refinements` сохраняются оба raw responses, разрешённые ID, длины prompt и Ollama metadata. Дополнительный вызов добавляет задержку: максимум один на каждую из прежних попыток выбора. Действительная краткость зависит от настоящего Qwen и ещё требует проверки.

Python дней 21–24, порог поиска, формат базы и история не изменены. Новые базы и `.env` в архив не входят. Пересборка индекса не требуется.

## Проверки

88 автоматических тестов PASS, включая новые проверки подмножества, неизменности question/requirements/provenance, недопустимых ID, unknown/malformed, token limit обеих стадий, orphan introduction и строгого отказа при удалении запрошенного доказательства. Интеграционные проверки используют scripted HTTP-модель; это не свидетельство качества реального Ollama. Чистые живые сценарии 12+12 пока не пройдены.

## Установка и один следующий шаг

Распакуйте архив в корень `ai-advent-llm-api` с заменой `day-25-rag-chat/`. Предыдущие исправления включены.

```bash
python day-25-rag-chat/main.py ask \
"Какой маршрут выбирается для --task info на день 20?" \
--session 4fb98ce5a966406688e4d80b51cfa7ba \
--output day-25-rag-chat/reports/check/long-info-v13.json
```

Ожидается прямое подтверждение, что `--task info` вызывает только GitHub, с источником. Цепочка полного `report` не должна появиться как маршрут info. Все четыре категории памяти должны сохраниться. По JSON отдельно проверяются свежие ветки поиска, первоначальный выбор, фактическое модельное подмножество, строгий audit, источники и дословность цитат.
