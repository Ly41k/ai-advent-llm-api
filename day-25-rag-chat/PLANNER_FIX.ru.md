# Исправление planner v1 — первый живой запрос дня 25

В пользовательском `first-chat.json` поиск был успешным: candidate_count=20, eligible_count=15, selected_count=5. Первый источник — `day-18-scheduled-mcp/README.ru.md`, cosine=0.6411369884936197. Причина отказа — `ambiguous_reference`: conversation planner вернул needs_clarification=true для самостоятельного вопроса «Какой процесс выполняет фоновые задания на день 18?». Выбор цитат и coverage ещё не вызывались. Кроме того, planner ошибочно записал вопрос в clarifications; цель осталась пустой.

Исправление:

- промпт разделяет неопределённый предмет вопроса и отсутствие знаний об ответе;
- model needs_clarification применяется к местоименным/эллиптическим продолжениям, а самостоятельный вопрос направляется в новый RAG-поиск и строгую проверку;
- вопросы, в том числе без знака вопроса, отклоняются как предложенные planner уточнения/ограничения/термины;
- первый самостоятельный пользовательский запрос задаёт начальную цель, если её нет; существующая цель сохраняется;
- исходный ответ модели, model_needs_clarification, effective_needs_clarification и причина корректировки остаются в trace;
- неоднозначное «А где это?» по-прежнему требует уточнения и не устанавливает фиктивную цель;
- strict validation, источник цитат и coverage-политика сохранены.

Сигнал местоимения/эллипсиса — консервативная эвристика, не доказательство семантической ясности. Окончательный ответ по-прежнему зависит от нового retrieval, выбора реальных quote IDs и coverage. Новые тесты воспроизводят точный неудачный planner JSON пользователя; селектор/coverage в локальных тестах остаются scripted HTTP-стендом. Настоящий Qwen после исправления в этой среде не запускался.

Проверено: 31 тест дня 25, включая два сценария по 12 ходов. Четыре новых теста покрывают исходный отказ, сохранение отказа при отсутствии доказательств, эллиптический запрос без местоимения и сохранение заданной цели.

## Применение

Выйти из текущего CLI через `/quit`. Архив содержит только изменённые Python-файлы дня 25, эту заметку, журнал тестов и manifest. Распаковать поверх корня проекта с заменой отдельных совпадающих файлов. Новые файлы не заменяют рабочие базы, main.py или всю папку дня 25.

Если архив сохранён в Downloads, команды из корня проекта:

```bash
unzip -o ~/Downloads/day-25-planner-fix-v1.zip
python day-25-rag-chat/test_day25.py -v
python day-25-rag-chat/main.py chat
```

Ожидается `Ran 31 tests` и `OK`. Последняя команда создаёт новую сессию; старый диалог сохраняется в базе. В новой сессии повторить один вопрос:

```text
Какой процесс выполняет фоновые задания на день 18?
```

Теперь самостоятельный вопрос должен доходить до выбора цитат и проверки доказательств. Это не гарантия положительного verdict от реального Qwen: если останется отказ, экспортировать новый trace и проверить его следующую конкретную причину.

```text
/export day-25-rag-chat/reports/check/first-chat-v2.json
```

Корпус/индекс, root README, параметры поиска и Python-модули дней 21–24 не менялись этим исправлением. Пересборка индекса не нужна. В старой сессии историческая ошибка сохраняется для диагностики; автоматически удалять пользовательскую память при применении патча приложение не будет. Если продолжать именно старую сессию, ошибочную запись можно убрать вручную:

```text
/forget clarifications 829b686f3578
```

После этого можно явно задать `/goal` либо пользоваться новой сессией, где цель инициализируется первым самостоятельным запросом.
