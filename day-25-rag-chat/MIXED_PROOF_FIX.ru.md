## Исправление

В v11 компактная инструкция для табличного ответа потеряла индекс соседних proof units, применявшийся в общей инструкции v7. В v12 этот индекс восстановлен и для смешанного ответа: таблица + код/цепочка/проза. Строки копируются дословно, в исходном порядке, только из разрешённых schema proof IDs одного claim/chunk. Перенос строки не обрывает стрелочную последовательность. Индекс ограничен; недостающие доказательства не добавляются.

Инструкция требует проверять связь цепочки с запрошенным маршрутом. Порядок строк обычной таблицы не считается порядком вызовов. Если часть порядка или связь с маршрутом не подтверждена, остаётся `covered=false`. Выполняется один audit; отрицательный семантический verdict не повторяется ради одобрения. Все исходные question/requirement/provenance/proof DATA и строгие валидаторы Day 24 сохранены.

Selector также получает короткую русскую инструкцию: цель/ограничения/терминология уточняют текущий вопрос, но не превращают его в запрос полного плана. Следует выбрать минимум полных цитат для всех запрошенных частей. Приложение не удаляет модельные quote IDs и не сокращает источники автоматически. Фактическую краткость ещё нужно проверить настоящим Qwen.

Python дней 21–24, порог поиска и базы данных не изменены.

```bash

"В каком порядке выполняется полный флоу дня 20?" \
--session 4fb98ce5a966406688e4d80b51cfa7ba \
--output day-25-rag-chat/reports/check/long-flow-v12.json
```
