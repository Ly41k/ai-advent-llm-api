# Связь вводной инструкции с командой v9

В `return-to-goal-v8.json` возврат к цели сработал: вопрос получил контекст дня 18, свежий поиск нашёл README дня 18, память полностью сохранилась, warnings/errors пусты, coverage положительный с первой попытки. Однако ручная проверка обнаружила ошибку связи фрагментов: после команды worker чат вывел «В терминале 2 … с GROQ_API_KEY». В README эта фраза относится к следующему блоку запуска `main.py`. Обе цитаты дословные, но их объединение вводит пользователя в заблуждение.

Поэтому навигация к цели и сохранность памяти прошли проверку, а качество этого ответа не прошло ручную проверку. Автоматический `covered=true` не заменяет просмотр источника.

## Изменения

- Из текущего каталога разрешённых цитат строятся связи короткой Markdown-фразы, заканчивающейся двоеточием, с непосредственно следующим fenced code block в том же чанке. Текст копируется дословно; названия процессов и ключей не зашиты в исправление.
- Селектор видит эти связи и инструкцию выбирать вводную фразу вместе с её следующей командой либо не выбирать её. Вводная фраза следующего процесса не является контекстом предыдущей команды.
- Приложение проверяет ответ селектора до coverage: если вводная фраза выбрана, её связанный блок должен идти сразу после неё. Оборванная или обратная последовательность отклоняется через существующий механизм исправления выбора цитат. При повторении ошибки ответ не публикуется.
- Исходный ответ модели сохраняется в тексте ошибки для диагностики. Цитаты не переписываются, не удаляются из принятого ответа автоматически и не дополняются за модель. Исправленную подборку вновь проверяет обычный строгий pipeline.
- Код команды без отдельной вводной фразы допустим, если он отвечает вопросу и проходит проверку доказательств. Неоднозначный запрос по-прежнему требует уточнения или достаточного контекста.

Индекс ограничен 16 связями и 8000 символами. Он не соединяет разные чанки или IDs вне schema. Эта структурная защита обнаруживает конкретный класс ошибок; она не является общей семантической проверкой всех возможных сочетаний цитат и не гарантирует краткость ответа.

Python-модули дней 21–24 не менялись. В адаптере `support25.py` добавлен экспорт существующего `EvidenceError` дня 24 для использования того же механизма отказа. Порог, строгая политика, базы и история не менялись.
