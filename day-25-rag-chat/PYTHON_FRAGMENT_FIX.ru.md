# v17 — Исключение лексически оборванного Python

## Основание

`first-collection-v16.json` правильно подтверждает немедленное назначение первого сбора через schedule_github_summary. Прямое доказательство — README; свежий RAG и источники работают. Однако ответ также содержит декоратор, def и открывающую строку docstring из server.py:10–12 без закрытия тройных кавычек. Это дословный фрагмент, но его нельзя считать целостным кодом. Исходный положительный audit сохранён, ручная проверка оформления не пройдена.

## Исправление

Перед selector исключается весь quote ID Python-фрагмента с незакрытой строкой/скобками. Обрабатываются цитаты из .py и явные fenced blocks python/py. `tokenize` из stdlib читает текст; источник не исполняется, не импортируется, не переписывается и не дополняется. В `validation.fragment_filters` записаны original text/quote_id/chunk_id и причина `python_unclosed_string_or_delimiter`. Если модель возвращает исключённый ID в обход schema, кандидат отвергается до audit.

Лексически целые отрывки, закрытые строковые литералы, код внутри функций, Markdown-проза и другие языки сохраняются. Проверка не требует полной функции или самостоятельной исполняемой программы. Guard таблиц работает прежним способом. Зависимости intro/code теперь фиксируются до всех фильтров: удаление плохого кода не скрывает зависимость на его ID и не создаёт новую смежность с посторонним кодом. Refiner по-прежнему выбирает только исходное подмножество; missing partner нельзя добавить.

Полный вопрос, requirements, оставшиеся literal quotes/provenance, память и RAG settings не меняются. Отрицательный coverage не заменяется, прежние две попытки нового кандидата и validators дня 24 сохранены. Days 21–24 Python не менялись; индекс пересобирать не требуется.

## Проверка

110 автоматических тестов PASS, включая прежние 2×12 scripted сценария и новые семь проверок: реальный оборванный docstring; строки/скобки; сохранение нормальных отрывков; whole-ID/schema guard; первоначальные зависимости после фильтрации; HTTP/SQLite ответ по точному README; отрицательный audit при отсутствии времени первого сбора. Реального Ollama в среде подготовки нет; живой повтор v17 и чистые полные 12+12 ещё обязательны.

## На Mac

Распакуйте архив в корень `ai-advent-llm-api` с заменой `day-25-rag-chat/`. Исправления v1–v17 включены; базы пользователя и `.env` исключены.

```bash
python day-25-rag-chat/main.py ask \
"Когда назначается первый сбор на день 18?" \
--session 7f95cd22a59c49a088a9f52d37726d5c \
--output day-25-rag-chat/reports/check/first-collection-v17.json
```

Проверим прямой ответ «сразу», источники дня 18, точные цитаты, сохранение сессии и исключение оборванного Python. Один status=answered не завершает ручную проверку.
