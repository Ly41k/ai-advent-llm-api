# День 25 — v23: сохранность памяти и экспорта

База обновления — опубликованный коммит `8f2b24fe0967011e796a42eb731287bbd55a9a42`.
Все опубликованные файлы сверены по Git blob SHA перед изменениями. Архив содержит только изменённые/новые файлы дня 25; существующие локальные SQLite-базы в него не входят.

## Два воспроизведённых дефекта

1. Две команды памяти могли прочитать одну версию состояния. Первая добавляла ограничение, а вторая сохраняла старый снимок с новой целью и стирала ограничение. Теперь `memory_command` передаёт прочитанную версию в `ChatStore.set_state`; UPDATE и запись события выполняются в одной транзакции с проверкой версии. При конфликте сохранённая память и журнал не меняются, CLI предлагает посмотреть `/state` и повторить команду. Изменения другой сессии не мешают.
2. `/export chats.db` или `--output` с путём SQLite-базы мог заменить базу JSON-текстом. Теперь общий `io25.py` проверяет пути базы истории, индекса и их `-wal`/`-shm`/`-journal`, включая символьные и жёсткие ссылки. Любой существующий файл с SQLite-заголовком защищён независимо от расширения. CLI отклоняет опасный `--output` до сохранения вопроса и обращения к модели. Интерактивный чат сообщает ошибку и продолжает работу. Обычный JSON сначала сериализуется, затем пишется во временный файл и атомарно заменяет отчёт; ошибка сериализации или замены сохраняет старый отчёт.

Также основной guard запрещает использовать жёсткие ссылки на один файл как якобы разные `--db` и `--chat-db`.

## Проверки

Добавлены 14 регрессионных тестов: конфликт двух соединений SQLite, устаревший `/forget`, завершённый ход между чтением/сохранением команды, изоляция сессий, базы/sidecars до создания, SQLite с расширением JSON, aliases, невалидный JSON, ошибка atomic replace, обычный экспорт, ранний отказ offline-demo, опасные выходные пути ask/export/evaluate, интерактивный отказ и hardlink общей базы.

Полный набор: 164 теста Day25 PASS. Результат в `reports/verified/release-v23-tests.txt`. Эти проверки используют локальные HTTP/LLM fixtures и не доказывают качество живого Qwen. Модельные prompts, retrieval, цитаты и coverage в v23 не менялись; код дней 21–24 также не менялся этим обновлением.

Живой пользовательский summary-route-v22 разобран и подтверждён отдельно: `reports/live/summary-route-v22-review.ru.md`. Цитата точна, маршрут верен, память сохранена. Новый полностью чистый живой прогон 12+12 на v23 не заявляется.

## Установка и короткая проверка

Из корня своего репозитория распакуйте `day-25-rag-chat-update-v23.zip` с заменой включённых файлов. Базы `chats.db` и `knowledge.db` не удаляйте.

```bash
python day-25-rag-chat/test_day25.py StoreTests JsonOutputTests -v
python day-25-rag-chat/test_day25.py -v
```

Это проверки без настоящей Ollama; полного часового живого прогона они не запускают. Ожидается 17 тестов в первом запуске и 164 во втором.

После коммита `8f2b24f` индекс, построенный до него, имеет старую revision: перед следующим обычным чатом выполните Day21 build/verify. Само распаковывание v23 не меняет индексируемый корпус и не требует повторной генерации эмбеддингов, если индекс уже соответствует текущему checkout. После следующего Git-коммита revision снова изменится.

```bash
python day-21-document-indexing/main.py build
python day-21-document-indexing/main.py verify
python day-25-rag-chat/main.py chat --session YOUR_SESSION_ID
```

Внутри `You>` можно проверить `/state`, `/export day-25-rag-chat/reports/check/v23-session.json`, затем намеренно `/export day-25-rag-chat/chats.db`: последний экспорт должен быть отклонён, а `/state` после него продолжать работать. Не вводите slash-команды в zsh.
