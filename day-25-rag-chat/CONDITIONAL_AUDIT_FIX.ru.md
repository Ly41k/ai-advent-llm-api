# v19 — Проверка действия в нужной условной ветке

## Основание

Живой premature-verify-v18 (ход 93) подтвердил структурное исправление v18: реальный Ollama принял enum, refiner удалил q1_9 с отсутствующим следующим блоком и оставил целый q1_11. Память и источники PASS. Ручной итог PARTIAL: q1_11 подтверждает selected by agent correction, но действие «выбирает следующий шаг» в выбранном предложении явно относится к HTTP 400 / fallback.

Явный двухчастный вопрос verify-behavior-v18 (ход 94) повторил ошибку: опубликован только q1_11, auditor переносит действие из ветки HTTP 400 в ветку преждевременного выбора. Его verification-observation ссылается на verified=true, хотя вопрос просит отметку исправления. Полная приёмка этого ответа FAIL. Источник, cosine, история и всё происхождение памяти корректны. Оба исходных JSON и честные ручные ревью сохранены в reports/live; положительные verdicts не переписаны задним числом.

## Исправление

- Selector и refiner получают общее правило: вопрос о реакции на ошибку требует действия именно при запрошенном условии и всех запрошенных отметок. Метка не доказывает действие; действие при другом условии переносить нельзя.
- Для prose proof unit с двумя условными частями, разделёнными точкой с запятой, auditor получает отдельное компактное представление. LITERAL CLAUSE INDEX содержит дословные части с offsets и исходными proof_id/quote_id/chunk_id. Semicolon внутри inline code не разделяется. Индекс — навигация; новые proof IDs, условия, действия или verdicts приложение не создаёт.
- В DATA сохраняются ВСЕ первоначальные proof_units, полный question_context, coverage_requirement и provenance. Другой выбранный proof может прямо подтверждать действие. История, память, невыбранные источники и первоначальные отклонённые ответы не передаются как доказательства.
- Auditor должен проверять действие и отметку для нужного условия, а observation трактовать в рамках текущего вопроса. Маркировка исправления не заменяется правилом завершения другой задачи. Для одного критерия остаётся один независимый semantic verdict; приложение не повторяет отрицательный audit до получения положительного.
- Исходные requirements/schema и validators дня 24 остаются. Если полнота не пройдена, strict policy отклоняет кандидат; прежняя вторая попытка выбирает новый ответ с feedback о недостающих фактах. Фильтры таблиц/Python, исходные зависимости intro/code, enum подмножеств, K20/5, cosine >=0.50, память и свежий RAG не ослаблены.

Trace `validation.conditional_audits` сохраняет исходный criterion ID, literal clause index, prompt size, raw verdict и Ollama metadata. Это помогает сверить, какая условная часть действительно подтверждает вывод. Новый helper ограничен 32 индексированными proofs/8000 символами; весь original DATA сохраняется независимо от бюджета индекса.

## Проверки

124 теста PASS: прежние 117 и семь новых. Проверены буквальные offsets реального предложения README, semicolon внутри inline code, сохранение всех proof units/schema без мутации, исключение чужих IDs/commands/tables, один отрицательный verdict без истории и approval retry. Два HTTP/SQLite сценария проверяют отказ на ответ с одной меткой при вопросе о действии и сохранение положительного ответа с прямым действием в другой цитате. Источники, память, история и две ветки свежего поиска сохраняются. Модельные результаты этих тестов scripted; качество Qwen здесь не заявляется.

Python дней 21–24 неизменён. Compilation и git diff --check PASS. Индекс для этого обновления пересобирать не нужно. Реального Ollama здесь нет; живой v19 и чистые полные 12+12 остаются обязательными.

## Следующий шаг на Mac

Распакуйте day-25-conditional-audit-fix-v19.zip в корень ai-advent-llm-api с заменой day-25-rag-chat/. Архив включает v1–v19; пользовательские базы и .env исключены.

```bash
python day-25-rag-chat/main.py ask \
"Как агент дня 20 исправляет преждевременный VERIFY: как выбирает допустимый следующий шаг и как отмечает исправление в выводе?" \
--session 587602c777d1483397cfd69ec151d32b \
--output day-25-rag-chat/reports/check/verify-behavior-v19.json
```

Проверить, что опубликованные цитаты прямо подтверждают выбор допустимого следующего шага при преждевременной операции и метку agent correction. Условие HTTP 400/fallback не может доказывать действие при преждевременном VERIFY. Отказ на недостаточный proof безопасен, но не завершает положительный сценарий. Не объявлять день 25 завершённым до всей приёмки.
