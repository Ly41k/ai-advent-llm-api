# Исправление короткого вопроса о порядке инструментов v7

В `topic-followup.json` память задачи полностью совпала с `topic-switch-v6.json`. Поиск выполнился заново: 20 кандидатов, 15 прошли порог, выбраны 5 чанков. В выбранном `day-20-mcp-orchestration/agent.py` цитата `q1_4` содержит многострочный `FLOW`, привязку `report` к этому списку и соответствие кодов операций инструментам. Все шесть выбранных цитат совпадают с локальными файлами в заявленных границах строк.

Тем не менее planner оставил короткий вопрос без указания дня. Coverage дважды вернул отрицательный verdict: признал наличие последовательности операций, но не признал её доказательством порядка вызова инструментов. Ответ был корректно заблокирован строгой политикой. Этот живой шаг проверки не пройден.

## Изменения

- Planner получает отдельную подсказку с единственным номером урока из последней принятой темы при неизменной памяти. Если модель оставляет короткий вопрос неизменным и сама считает ссылку разрешённой, приложение добавляет только наблюдаемый номер урока как контекст поиска. Цель задачи не меняется; названия инструментов и факты в вопрос не добавляются.
- Явно указанный день, возврат к цели, неоднозначность модели, несколько уроков, изменение памяти или промежуточное сообщение с другой темой блокируют эту подстановку. При повторе идентичного нераскрытого вопроса можно пройти через последовательные такие повторы к предыдущей теме.
- Аудитор получает ограниченный индекс последовательных дословных proof units. Нельзя соединять разные claims/цитаты, чанки, отсутствующие или запрещённые schema идентификаторы. Большие блоки пропускаются целиком; текст не переписывается и не выполняется.
- Промпт объясняет, что порядок может быть прямо задан в многострочном кортеже/списке или диаграмме, если источник также связывает его с запрошенной задачей. Список имён без порядка, случайное расположение имён в файле или коды без связи с инструментами недостаточны. По запросу дополнительных деталей нужны дополнительные доказательства.
- Селектору предлагается выбирать последовательность и её связь с задачей, без полного runner, схемы API и обработки ошибок, если они не запрошены. Это инструкция модели, а не гарантия краткости.

Список инструментов не зашит в исправление. Verdict по-прежнему принимает модель; отрицательный verdict не превращается в положительный. Строгая политика, порог и Python-модули дней 21–24 не менялись.

## Проверка

52 теста дня 25 прошли. Добавлены проверки продолжения новой темы после перезапуска и нового retrieval, запретов на подстановку темы, точности и границ блоков, сохранности состояния и неизменности отрицательного verdict. Два технических сценария по 12 ходов входят в тесты, но используют scripted fixture, а не настоящий Qwen.

В реплее настоящего `topic-followup.json` неизменённый вопрос получает контекст дня 20, память не меняется, строки блоков остаются дословными, оригинальный отрицательный ответ аудитора сохраняется. Результат находится в `reports/verified/sequence-trace-replay.json`; журнал тестов — `reports/verified/sequence-fix-tests.txt`. Положительный ответ настоящего Qwen после этого изменения ещё не проверен.

## Применение

Архив содержит накопленные исправления v1–v6. Распаковать поверх корня проекта. Рабочих баз и истории в архиве нет; пересборка индекса и миграция базы чата не нужны.

```bash
unzip -o ~/Downloads/day-25-sequence-fix-v7.zip
python day-25-rag-chat/test_day25.py -v
python day-25-rag-chat/main.py ask \
"А в каком порядке вызываются инструменты для полного отчёта?" \
--session 2cb61350c3d54c218d260e6a5cd65969 \
--output day-25-rag-chat/reports/check/topic-followup-v7.json
```

Ожидается `Ran 52 tests` и `OK`, затем ответ о порядке инструментов полного отчёта дня 20 с подтверждёнными источниками и сохранением прежней цели/памяти дня 18. При отказе нужно проверить новое раскрытие вопроса, выбранные цитаты и raw coverage. Проверка всей задачи, особенно двух длинных живых сценариев, остаётся отдельным следующим этапом.
