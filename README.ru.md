# День 8 — работа с токенами

Восьмое задание показывает, как текущий запрос, сохранённая история и ответ модели занимают контекстное окно и влияют на стоимость API.

## Задание

- считать токены текущего запроса, всей истории и ответа модели;
- сравнить короткий, длинный и переполненный диалог;
- показать рост токенов и стоимости;
- продемонстрировать, что ломается при превышении лимита модели.

## Результат

`BublikAgent` выполняет два взаимодополняющих измерения:

1. До API-вызова `GptOssTokenCounter` использует кодировку GPT-OSS `o200k_harmony` и оценивает текущий запрос, историю и полный prompt.
2. После API-вызова `response.usage` предоставляет фактическое количество оплачиваемых prompt, completion и total tokens от Groq.

Локальная оценка позволяет заранее проверить контекст. Данные API позволяют рассчитать стоимость отдельного запроса и всего диалога.

## Структура

```text
day-08-token-usage/
├── agent.py
├── experiment.py
├── main.py
├── memory.py
├── tokens.py
├── README.md
└── README.ru.md
```

- `tokens.py` отвечает за подсчёт токенов, лимиты, цены и метрики;
- `agent.py` проверяет контекст и объединяет оценку с данными Groq;
- `memory.py` сохраняет статистику каждого завершённого запроса;
- `main.py` запускает интерактивного агента;
- `experiment.py` сравнивает три истории без API-вызовов.

## Отображаемые метрики

После ответа CLI показывает токены текущего запроса и истории, оценку и фактический размер prompt, completion tokens, токены видимого ответа, общее количество токенов и стоимость.

Completion tokens и токены видимого ответа могут отличаться: GPT-OSS является reasoning-моделью, поэтому статистика провайдера может включать скрытые токены рассуждений.

## Защита контекста

Текущее контекстное окно GPT-OSS 20B в Groq составляет 131 072 токена. Агент резервирует 1 200 токенов для ответа и проверяет:

```text
оценка prompt + резерв ответа <= контекстное окно
```

Если запрос не помещается, `ContextWindowExceededError` возникает до его сохранения и отправки. Без этой проверки провайдер отклонит переполненный запрос.

## Стоимость

В примере используются текущие цены GPT-OSS 20B: `$0.075` за 1 миллион входных и `$0.30` за 1 миллион выходных токенов.

```text
стоимость = input_tokens × цена input + output_tokens × цена output
```

Константы служат учебным снимком, перед реальным расчётом биллинга их необходимо перепроверять.

## Запуск

Установите зависимости и запустите интерактивного агента:

```bash
pip install -r requirements.txt
python day-08-token-usage/main.py
```

Команды:

- `/history` — история текущего диалога;
- `/stats` — накопленные фактические токены и стоимость;
- `/dialogs` — переключение диалога;
- `/exit` или `выход` — завершение.

Запуск воспроизводимого сравнения:

```bash
python day-08-token-usage/experiment.py
```

Оно создаёт короткий диалог с 1 обменом, длинный со 100 обменами и переполненный с 1 500 обменами. Для допустимых сценариев эксперимент также суммирует входные, выходные и общие токены всех завершённых обменов и их расчётную стоимость. Groq не вызывается, API-кредиты не расходуются.

## Главное наблюдение

Каждый запрос повторно отправляет выбранную историю. Поэтому prompt растёт, поздние сообщения стоят дороже, а накопленное количество оплачиваемых входных токенов увеличивается быстрее объёма уникального текста.

В определённый момент история вместе с резервом ответа перестаёт помещаться. Тогда старые сообщения нужно удалить, суммировать, заменить релевантными фрагментами или выбрать модель с более широким контекстом.

## Текущие ограничения

- локальный размер prompt является оценкой; для биллинга приоритетны данные Groq;
- полная история намеренно передаётся для демонстрации переполнения;
- усечение и суммаризация пока отсутствуют;
- цены и лимиты могут измениться;
- стоимость кэшированных токенов не учитывается.

## Итог восьмого дня

Бублик показывает расход токенов, сохраняет стоимость каждого завершённого обмена и останавливает переполненные запросы до обращения к модели.
